기존 Astra·Fable 원고 300편을 NDL 1.1 기준으로 보완하고 Qwen을 다시 학습했습니다. 새 문제 24개로 원고를 두 번씩 생성해 비교했습니다. 분량을 지킨 원고는 학습 전 0/48편에서 15/48편으로 늘었고 평균 어휘 포함률은 87.1%에서 92.2%로 올랐습니다. 그러나 Astra의 전체 선호 비교에서는 학습 전 모델에 10승 14패였고 이름과 사건이 달라지는 오류도 남았습니다. 이번 학습본은 운영에 도입하지 않습니다.

이 글은 원고 수정, 이름 정보 수정, 로컬 <span class="term" data-tip="Supervised Fine-Tuning. 입력과 목표 응답 쌍을 주고 다음 토큰 손실을 줄이도록 모델을 추가 학습하는 단계. 선호쌍을 비교하는 DPO와 데이터 형식과 목적이 다르다.">SFT</span>, 메모리 부족을 겪고 복구한 과정, 마지막 비교 결과까지 정리했습니다. 학습 원고는 251편을 수정하고 49편은 그대로 사용했습니다. 최종 원고의 평균 NDL 포함률은 85.3%입니다. 학습 데이터의 어휘를 바꾼 뒤 새 출력의 품질도 나아졌는지 확인했습니다. 자동 검사와 원문 대조 결과는 따로 정리했습니다.

## 1. 이전 실험 결과 다시 보기

[이전 학습 글](/posts/qwen-astra-fable-distillation-arena/)의 0/24 → 7/24는 180~230단어 분량을 지킨 비율입니다. 동화 전체의 품질이 그만큼 올랐다는 뜻은 아닙니다. 후속 실험은 별도로 고정한 24문제에서 생성 설정과 <span class="term" data-tip="동결한 베이스 모델 옆에 붙여 학습하는 작은 추가 가중치 묶음. 파일이 작아도 층 이름과 배열 모양이 실행 프레임워크의 형식과 맞지 않으면 그대로 옮겨 쓸 수 없다.">어댑터</span> 기여를 바꿨고 같은 문제의 기존 학습본은 분량 11/24, 수정 후보는 6/24였습니다. 반복 경고는 4편에서 0편으로 줄었지만 이름과 관계가 바뀐 사례는 남았습니다.

NDL 실험에서는 어휘, 분량, 반복, 이름·관계, 사건 보존을 따로 기록합니다. 분량을 잘 맞췄더라도 이름이나 사건이 바뀌었다면 별도로 확인해야 하기 때문입니다. 마지막 비교에 쓸 새 문제 24개와 시드 두 개는 미리 고정하고 학습에 넣지 않았습니다. 학습 전 모델과 이전 학습본의 비교 원고는 먼저 생성했지만 새 가중치를 고르기 전에는 결과 내용을 열어보지 않았습니다.

## 2. NDL 목록과 어휘 분석기

NDL 1.1은 Browne와 Culligan이 개발한 어린 학습자용 874개 headword 목록입니다. 공식 사이트가 제공하는 teaching list, research list, 순위 자료를 원본 그대로 보관하고 SHA-256을 기록했습니다.[^ndl]

로컬 분석기는 teaching list에 명시된 어형을 기준으로 단어 출현 횟수를 셉니다. `can't` 같은 축약형을 풀고 확인한 고유명사 표기는 별도로 제외합니다. 대문자 이름 `Pat`을 제외하더라도 동사 `pat`까지 지우지 않습니다. 이름이 목록 밖이라는 이유로 글을 더 어렵다고 계산하거나 이름을 다른 단어로 바꾸는 오류를 피하려는 처리입니다.

| 기준 | 기존 학습 원고 300편 |
|---|---:|
| 고유명사를 포함한 평균 포함률 | 76.7% |
| 고유명사 제외 후 평균 포함률 | 79.7% |
| 고유명사 제외 후 중앙값 | 79.5% |
| 포함률 85% 이상 | 45편 |
| 포함률 90% 이상 | 5편 |
| 포함률 95% 이상 | 0편 |

공식 Text Profiler와 구현이 같은지는 별도로 검증하지 않았습니다. 소유격과 축약형의 모호함, 명사 식별 누락, 목록에 없는 굴절형도 남아 있습니다. 숫자·문장부호 처리와 고유명사 제외 규칙을 고정하고 두 목록의 결과를 함께 보관했습니다. 어휘 포함률을 <span class="term" data-tip="영어 독자의 읽기 능력과 텍스트 난이도를 같은 척도에 표시하는 상용 지표. 텍스트 측정은 어휘의 빈도와 문장 길이 같은 특성을 사용하며, 이 프로젝트의 가독성 공식 합성값은 공인 Lexile이 아니다.">Lexile</span>이나 CEFR, 독해 능력으로 환산하지 않았습니다.

## 3. 20편 예비 실험에서 만난 출력 한도

첫 요청에는 NDL headword 874개와 원문을 모두 넣었습니다. 20편 중 완성 응답은 14편이었고 나머지 6편은 Fable의 출력 한도에 도달했습니다. 사용량을 확인하니 <span class="term" data-tip="일부 추론 모델이 최종 답을 내기 전에 사용하는 내부 계산 토큰으로 API usage에 별도 집계될 수 있다. 과금 포함 여부와 단가는 모델·공급자 정책을 확인해야 한다.">추론 토큰</span>이 900토큰 한도의 대부분을 차지했습니다. 추론을 응답에서 숨기는 설정은 추론 계산을 끄는 설정이 아니었습니다.[^reasoning]

실패 응답도 비용 원장에 남겼습니다. 첫 20편의 확인 비용은 $1.103115입니다. 빈 응답은 원고 수에서 제외하되 발생한 비용은 그대로 집계했습니다.

두 번째 요청에서는 긴 단어 은행을 뺐습니다. 대신 원고에서 목록 밖으로 잡힌 표현과 문맥에 맞는 대체 예를 전달했습니다. Fable 출력 한도는 1,600토큰으로 늘렸습니다. 20편 중 19편이 완성됐지만 분량을 지킨 것은 16편이었습니다. 이 16편을 같은 원문과 비교하면 평균 포함률은 78.3%에서 86.8%로 올랐습니다. 이 수치는 완성하지 못하거나 분량 조건을 벗어난 4편을 뺀 결과입니다.

## 4. 단어를 쉽게 바꾸면서 놓친 내용

NDL 밖으로 잡힌 표현에는 `feather`, `pillow`, `leaf`도 있었습니다. 이야기의 핵심 물건을 없애거나 같은 명사를 모두 대명사로 바꾸면 포함률은 올라가도 장면을 이해하기 어려워집니다. 짧은 문장을 반복해 분모를 늘리는 방법도 도움이 되지 않습니다.

실제 수정본에서 두 개의 파란 깡통이 일반 상자로 바뀌고 지난 화요일이 지난주로 바뀐 사례가 있었습니다. 핵심 줄거리를 유지한 원고에서도 세부 정보는 달라졌습니다. 원문과 수정본의 차이를 보관하고 대조해 이런 변경을 되돌리거나 해당 수정본을 제외합니다. 의미가 보존됐는지는 분량·종료 여부·이름 검사만으로 확인하기 어려웠습니다.

나머지 원고는 기존 Astra·Fable 원문을 바탕으로 Astra가 표현을 다듬었습니다. 시험에서 Fable의 추론 비용과 잘림이 커서 제한된 예산으로 반복 호출하기 어렵다고 판단했습니다. 원 저자 모델과 수정 모델을 따로 기록하며 모든 원고가 90%를 달성했다고 표시하지 않습니다.

## 5. 학습 원고 300편과 LoRA 설정

학습 원고 300편 중 251편은 수정본을 채택했고 49편은 원문을 유지했습니다. 첫 집계에서 원고의 평균 NDL 포함률은 79.7%에서 85.4%로, 90% 이상인 원고는 5편에서 49편으로 바뀌었습니다. 여기까지는 학습 데이터가 얼마나 바뀌었는지를 집계한 결과입니다. 모델이 새로 생성한 글은 뒤에서 비교합니다. 90%를 못 채운 원고에 90%라는 조건을 붙이지 않고 실제 포함률을 5%p 단위로 내린 값을 입력 조건으로 사용했습니다. 이 구간 역시 공식 NDL 읽기 단계가 아닙니다.

이름과 가족 관계를 입력에 명시했습니다. 비고전 학습 사례 32편은 입력과 정답의 이름을 함께 새로운 가상 이름으로 바꿨습니다. 새 평가용 이름은 이 치환 목록에 넣지 않았고 이름을 원래대로 되돌리면 원문과 정확히 일치하는지도 확인했습니다. 익숙한 이름을 외우기보다 입력에 주어진 이름을 유지하도록 학습시키려는 목적이었습니다.

학습 300편과 검증 24편의 작품 그룹은 겹치지 않습니다. 수정된 모든 입력·정답 쌍은 최대 893토큰으로, 설정한 1,024토큰 안에 들어가 잘리지 않습니다. <span class="term" data-tip="원본 가중치는 얼려 두고 곁에 붙인 작은 저랭크 행렬(어댑터)만 학습하는 파인튜닝 기법. 학습 대상이 전체의 1% 미만이라 메모리와 시간이 크게 줄고, 어댑터만 따로 저장·교체할 수 있다.">LoRA</span>는 기반 모델에서 새로 학습합니다. 마지막 8개 층, rank 16, 학습률 0.000005, 300번 업데이트로 정했습니다. 이전 rank 32·학습률 0.00001보다 낮은 rank와 학습률을 선택했지만 데이터와 설정을 함께 바꾸므로 어느 하나의 단독 효과라고 설명할 수는 없습니다.

150번과 300번 시점의 가중치를 저장하고 검증 원고 24편의 손실과 사전에 고른 검증용 생성 문제 6개로 최종 가중치를 선택합니다. 새 평가 24문제로 가중치를 고르거나 학습 원고를 다시 수정하지 않습니다.

전체 324편은 분량·종료 여부·이름·관계 어휘·수량과 날짜 변경을 코드로 점검했습니다. 별도로 첫 20편과 추가 14개 사례를 대조해 읽었지만 모든 원고를 사람이 의미 검수한 것은 아닙니다. 이 글에서 말하는 원문 대조는 코딩 에이전트의 검토입니다. 독립적인 사람 평가는 진행하지 않았습니다. 자동 점검은 관계어가 나오지 않는 인물 교체나 인과관계 오류를 놓칠 수 있습니다. 삼각형 조각이 틈으로 기울어지는 장면을 수정본이 ‘휘어진다’로 바꾼 경우는 직접 대조해 원래 의미로 복원했습니다.

## 6. 새 문제와 평가 기준

학습 전 Qwen, 이전 학습본의 가중치 기여를 절반으로 한 조건, 새 학습본을 같은 요청과 생성 설정으로 비교합니다. 세 조건 모두 이번 NDL 요청을 사용하므로 이전 글의 점수와 절댓값을 이어 붙이지 않습니다. 로컬 학습과 추론만 수행하며 운영 앱에는 연결하지 않습니다.

새 문제는 인물 관계, 끝이 있는 사건 전개, 물건의 상태·수량을 각 8개씩 묻는 24개입니다. 두 시드의 48개 출력에서 분량·반복·NDL 포함률과 이름·관계 경고를 확인합니다. 통계는 문제별로 묶어서 비교합니다. 같은 문제에서 만든 두 출력을 독립된 두 문제로 세지 않기 위해서입니다.

선호 평가는 첫 번째 시드의 출력만 사용합니다. Astra가 24문제의 모든 모델 쌍을 순서를 바꿔 비교하고 Fable은 결과를 보기 전에 고른 6문제로 교차 확인합니다. 학습 원고를 만든 교사 모델이 심판도 맡습니다. 이 점수만으로 문학적 우열을 객관적으로 가렸다고 보기는 어렵습니다. 두 심판의 표본 수가 달라 주 순위에 합치지 않고 따로 기록했습니다.

추가 <span class="term" data-tip="소프트웨어가 다른 소프트웨어의 기능이나 데이터에 접근할 때 따르는 호출 계약. 사용할 주소, 입력 형식, 인증, 응답과 오류 규칙을 함께 정의한다.">API</span> 예산은 최대 $15, 기존 작업을 포함한 누적 상한은 $55입니다. 원고 수정 단계의 확인 비용은 $8.790255입니다. 실패·잘린 응답도 포함합니다. 실제 사용액과 비용을 확인하지 못한 호출의 예약액을 함께 계산해 요청 전에 한도를 검사합니다. 최종 비교 결과와 전체 비용은 아래 11~14절에 기록했습니다.

## 7. 이름 분류 오류로 학습 중단

검증용 사례를 원문과 대조하다가 인물 목록에 들어간 `Biscuit`이 반려동물 이름이 아니라 간식이라는 것을 발견했습니다. 학습 원고에도 같은 문제가 있는지 찾아봤습니다. 두드리는 소리 `Pat, pat`, 종소리 `Ling`, 움직임을 뜻하는 `Bob`, 형용사 `Sandy`가 인물 이름으로 분류된 사례가 있었습니다. 알려진 이름 목록에 있는 단어라고 해서 해당 문맥에서도 이름인 것은 아니었습니다.

이 상태로 이름을 유지하라고 학습하면 실제 인물과 소리를 혼동하는 신호를 줄 수 있습니다. 로컬 학습을 멈추고 해당 문맥을 읽었습니다. 이후 16개 사례에 이름 제외 규칙을 적용했습니다. 실제 개와 고양이의 이름인 `Biscuit`은 유지했습니다. 검증용 원고의 인물 목록에서 빠진 `Tully`, `Scratch`, `Clatter`도 추가했습니다.

가족 관계도 `auntie`와 `granny` 같은 별칭을 빠뜨리지 않도록 수정했습니다. 배우자 `wife`가 등장하는 검증 원고에 가족 관계가 없다고 표시한 오류도 바로잡았습니다. 이름·관계 정보가 달라진 사례는 학습·검증을 합쳐 21개입니다. 정답 원고와 32편의 이름 치환 결과는 바꾸지 않았습니다.

## 8. 쉬운 단어로 바꾸자 늘어난 비슷한 표현

## 10. 자동 검사가 놓친 원고 오류

복구 학습 150회를 끝내고 가중치를 저장했습니다. 이는 처음 저장한 150회와 합쳐 300회 업데이트를 거친 가중치입니다. 다만 중간에 Adam을 초기화했으므로 연속으로 300회 학습한 경우와는 다릅니다.

최종 비교 원고를 읽을 때는 첫 시드의 세 모델 원고 72편에서 모델 이름을 가리고 확인했습니다. 새 학습본은 두 번째 시드 24편도 모두 읽고 나머지 조건의 두 번째 시드에서는 자동 경고가 난 9편을 추가로 보았습니다. 이 원문 검토도 코딩 에이전트가 수행했습니다. 사람이나 교육 전문가가 검수한 결과는 아닙니다. 새 평가 결과를 본 뒤 가중치를 다시 고르지 않았습니다.

## 13. 다음 실험에서 확인할 것

검증 손실은 기반 모델 1.9333에서 선택한 저장본 1.5552로 낮아졌습니다. 목표 원고의 다음 단어를 더 잘 예측하게 됐지만 새 문제의 제약을 더 잘 지켰다는 결과는 아니었습니다.

Astra의 축별 판정도 다르게 움직였습니다. 학습 전 모델 대비 새 학습본은 언어·독자 적합성에서 18승 1무 5패였지만 이야기 구조에서는 6승 4무 14패, 독창성·분위기에서는 6승 5무 13패였습니다. 축별 판정은 전체 판정에 사용한 심판 응답에서 함께 받은 결과입니다. 별도의 독립 실험은 아닙니다. 표현이 쉬워진 원고에서 사건 전개는 약해지는 경향을 확인하는 데 참고했습니다.

이 결과만으로 NDL이나 낮은 rank가 오류의 원인이라고 확정할 수는 없습니다. 원고 수정, 이름 정보, rank, 학습률, 메모리 복구 절차를 함께 바꿨습니다. 학습 원고도 일상 장면이 많고 이번 평가는 이름·수량·행동 순서 제약을 따로 강조했습니다. 원인별 기여를 분리하려면 다음 실험이 필요합니다.

1. 같은 입력의 원문과 어휘 수정본을 고정하고 학습 설정을 같게 둡니다. 이렇게 어휘 수정의 효과부터 분리합니다.
2. 인물 목록에 이름과 관계어를 따로 나열하는 대신 `이름 → 관계 → 행동 → 소유물`을 묶은 입력과, 사건이 끝날 때의 상태를 보존한 정답을 검증 자료부터 준비합니다.
