기존 Astra·Fable 원고 300편을 NDL 1.1 목록으로 분석했습니다. 고유명사를 제외한 단어 출현 기준 평균 포함률은 79.7%였고, 90% 이상인 원고는 5편이었습니다. 이 수치는 아이의 읽기 능력 점수가 아닙니다. 이번에는 쉬운 어휘와 인물 정보를 함께 반영해 Qwen을 다시 <span class="term" data-tip="Supervised Fine-Tuning. 입력과 목표 응답 쌍을 주고 다음 토큰 손실을 줄이도록 모델을 추가 학습하는 단계. 선호쌍을 비교하는 DPO와 데이터 형식과 목적이 다르다.">SFT</span>하려 합니다. 251편은 수정본을 채택하고 49편은 원문을 유지했습니다. 인물 이름 집계를 바로잡은 현재 평균 포함률은 85.3%입니다. 아래는 **로컬 재학습이 진행 중인 기록**이며, 모델의 품질 개선은 아직 확인되지 않았습니다.

## 1. 이전 표가 보여주는 범위를 먼저 구분했습니다

[이전 학습 글](/posts/qwen-astra-fable-distillation-arena/)의 0/24 → 7/24는 180~230단어 분량을 지킨 비율입니다. 동화 전체의 품질이 그만큼 올랐다는 뜻은 아닙니다. 후속 실험은 별도로 고정한 24문제에서 생성 설정과 <span class="term" data-tip="동결한 베이스 모델 옆에 붙여 학습하는 작은 추가 가중치 묶음. 파일이 작아도 층 이름과 배열 모양이 실행 프레임워크의 형식과 맞지 않으면 그대로 옮겨 쓸 수 없다.">어댑터</span> 기여를 바꿨고, 같은 문제의 기존 학습본은 분량 11/24, 수정 후보는 6/24였습니다. 반복 경고는 4편에서 0편으로 줄었지만, 이름과 관계가 바뀐 사례는 남았습니다.

NDL 실험에서는 어휘, 분량, 반복, 이름·관계, 사건 보존을 따로 기록합니다. 한 지표의 상승으로 다른 오류를 덮지 않으려는 선택입니다. 마지막 비교에는 이번 학습에 넣지 않는 새 문제 24개와 시드 두 개를 먼저 고정했습니다. 학습 전 모델과 이전 학습본의 비교 원고는 생성했지만, 새 가중치를 고르기 전에는 결과 내용을 열어보지 않습니다.

## 2. 공식 목록과 로컬 분석기의 범위를 정했습니다

NDL 1.1은 Browne와 Culligan이 개발한 어린 학습자용 874개 headword 목록입니다. 공식 사이트가 제공하는 teaching list, research list, 순위 자료를 원본 그대로 보관하고 SHA-256을 기록했습니다.[^ndl]

로컬 분석기는 teaching list에 명시된 어형을 기준으로 단어 출현 횟수를 셉니다. `can't` 같은 축약형을 풀고, 확인한 고유명사 표기는 별도로 제외합니다. 대문자 이름 `Pat`을 제외하더라도 동사 `pat`까지 지우지 않습니다. 이름이 목록 밖이라는 이유로 글을 더 어렵다고 계산하거나 이름을 다른 단어로 바꾸는 오류를 피하려는 처리입니다.

| 기준 | 기존 학습 원고 300편 |
|---|---:|
| 고유명사를 포함한 평균 포함률 | 76.7% |
| 고유명사 제외 후 평균 포함률 | 79.7% |
| 고유명사 제외 후 중앙값 | 79.5% |
| 포함률 85% 이상 | 45편 |
| 포함률 90% 이상 | 5편 |
| 포함률 95% 이상 | 0편 |

공식 Text Profiler와 동일한 구현이라고 검증한 것은 아닙니다. 소유격과 축약형의 모호함, 명사 식별 누락, 목록에 없는 굴절형도 남아 있습니다. 숫자·문장부호 처리와 고유명사 제외 규칙을 고정하고 두 목록의 결과를 함께 보관했습니다. 어휘 포함률을 <span class="term" data-tip="영어 독자의 읽기 능력과 텍스트 난이도를 같은 척도에 표시하는 상용 지표. 텍스트 측정은 어휘의 빈도와 문장 길이 같은 특성을 사용하며, 이 프로젝트의 가독성 공식 합성값은 공인 Lexile이 아니다.">Lexile</span>이나 CEFR, 독해 능력으로 환산하지 않았습니다.

## 3. 20편 시험에서 출력 한도 문제가 드러났습니다

첫 요청에는 NDL headword 874개와 원문을 모두 넣었습니다. 20편 중 완성 응답은 14편이었고, 나머지 6편은 Fable의 출력 한도에 도달했습니다. 사용량을 확인하니 <span class="term" data-tip="일부 추론 모델이 최종 답을 내기 전에 사용하는 내부 계산 토큰으로 API usage에 별도 집계될 수 있다. 과금 포함 여부와 단가는 모델·공급자 정책을 확인해야 한다.">추론 토큰</span>이 900토큰 한도의 대부분을 차지했습니다. 추론을 응답에서 숨기는 설정은 추론 계산을 끄는 설정이 아니었습니다.[^reasoning]

실패 응답도 비용 원장에 남겼습니다. 첫 20편의 확인 비용은 $1.103115입니다. 빈 응답을 원고로 집계하거나 무료 실패로 처리하지 않았습니다.

두 번째 요청은 긴 단어 은행을 빼고, 원고에서 목록 밖으로 잡힌 표현과 문맥에 맞는 대체 예를 전달했습니다. Fable 출력 한도는 1,600토큰으로 늘렸습니다. 20편 중 19편이 완성됐지만 분량을 지킨 것은 16편이었습니다. 이 16편을 같은 원문과 비교하면 평균 포함률은 78.3%에서 86.8%로 올랐습니다. 완성하지 못하거나 길이가 벗어난 4편을 제외한 조건부 수치입니다.

## 4. 포함률만 높이는 수정은 채택하지 않습니다

NDL 밖으로 잡힌 표현에는 `feather`, `pillow`, `leaf`도 있었습니다. 이야기의 핵심 물건을 없애거나 같은 명사를 모두 대명사로 바꾸면 포함률은 올라가도 장면을 이해하기 어려워집니다. 짧은 문장을 반복해 분모를 늘리는 방법도 도움이 되지 않습니다.

실제 수정본에서 두 개의 파란 깡통이 일반 상자로 바뀌고, 지난 화요일이 지난주로 바뀐 사례가 있었습니다. 핵심 줄거리가 유지돼도 세부 정보는 달라질 수 있었습니다. 원문과 수정본의 차이를 보관하고 이런 변경은 복원하거나 수정본 채택에서 제외합니다. 분량·종료 여부·이름 검사만 통과했다고 의미 보존이 확인된 것은 아닙니다.

나머지 원고는 기존 Astra·Fable 원문을 바탕으로 Astra가 표현을 다듬었습니다. 시험에서 Fable의 추론 비용과 잘림이 커서 제한된 예산으로 반복 호출하기 어렵다고 판단했습니다. 원 저자 모델과 수정 모델을 따로 기록하며, 모든 원고가 90%를 달성했다고 표시하지 않습니다.

## 5. 300편을 고정하고 로컬 재학습을 시작했습니다

학습 원고 300편 중 251편은 수정본을 채택했고, 49편은 원문을 유지했습니다. 첫 집계에서 원고의 평균 NDL 포함률은 79.7%에서 85.4%로, 90% 이상인 원고는 5편에서 49편으로 바뀌었습니다. 이는 **학습 데이터의 변화**이며 모델이 생성한 새 글의 결과가 아닙니다. 90%를 못 채운 원고에 90%라는 조건을 붙이지 않고, 실제 포함률을 5%p 단위로 내린 값을 입력 조건으로 사용했습니다. 이 구간 역시 공식 NDL 읽기 단계가 아닙니다.

이름과 가족 관계를 입력에 명시했습니다. 비고전 학습 사례 32편은 입력과 정답의 이름을 함께 새로운 가상 이름으로 바꿨습니다. 새 평가용 이름은 이 치환 목록에 넣지 않았고, 이름을 원래대로 되돌리면 원문과 정확히 일치하는지도 확인했습니다. 익숙한 이름을 외우는 대신 입력에 주어진 이름을 유지하는 연습을 추가하려는 선택입니다.

학습 300편과 검증 24편의 작품 그룹은 겹치지 않습니다. 수정된 모든 입력·정답 쌍은 최대 893토큰으로, 설정한 1,024토큰 안에 들어가 잘리지 않습니다. <span class="term" data-tip="원본 가중치는 얼려 두고 곁에 붙인 작은 저랭크 행렬(어댑터)만 학습하는 파인튜닝 기법. 학습 대상이 전체의 1% 미만이라 메모리와 시간이 크게 줄고, 어댑터만 따로 저장·교체할 수 있다.">LoRA</span>는 기반 모델에서 새로 학습합니다. 마지막 8개 층, rank 16, 학습률 0.000005, 300번 업데이트로 정했습니다. 이전 rank 32·학습률 0.00001보다 업데이트 크기를 줄였지만, 데이터와 설정을 함께 바꾸므로 어느 하나의 단독 효과라고 설명할 수는 없습니다.

150번과 300번 시점의 가중치를 저장하고, 검증 원고 24편의 손실과 사전에 고른 검증용 생성 문제 6개로 최종 가중치를 선택합니다. 새 평가 24문제로 가중치를 고르거나 학습 원고를 다시 수정하지 않습니다.

전체 324편은 분량·종료 여부·이름·관계 어휘·수량과 날짜 변경을 코드로 점검했습니다. 별도로 첫 20편과 추가 14개 사례를 대조해 읽었지만, 모든 원고를 사람이 의미 검수한 것은 아닙니다. 자동 점검은 관계어가 나오지 않는 인물 교체나 인과관계 오류를 놓칠 수 있습니다. 삼각형 조각이 틈으로 기울어지는 장면을 수정본이 ‘휘어진다’로 바꾼 경우는 직접 대조해 원래 의미로 복원했습니다.

## 6. 새 비교에서는 어휘와 동화 품질을 분리합니다

학습 전 Qwen, 이전 학습본의 가중치 기여를 절반으로 한 조건, 새 학습본을 같은 요청과 생성 설정으로 비교합니다. 세 조건 모두 이번 NDL 요청을 사용하므로 이전 글의 점수와 절댓값을 이어 붙이지 않습니다. 로컬 학습과 추론만 수행하며 운영 앱에는 연결하지 않습니다.

새 문제는 인물 관계, 끝이 있는 사건 전개, 물건의 상태·수량을 각 8개씩 묻는 24개입니다. 두 시드의 48개 출력에서 분량·반복·NDL 포함률과 이름·관계 경고를 확인합니다. 통계에서는 같은 문제의 두 출력을 독립된 두 문제로 세지 않고, 문제별로 묶어서 비교합니다.

선호 평가는 첫 번째 시드의 출력만 사용합니다. Astra가 24문제의 모든 모델 쌍을 순서를 바꿔 비교하고, Fable은 결과를 보기 전에 고른 6문제로 교차 확인합니다. 원고를 학습시킨 교사 모델이 심판이기도 하므로, 이 점수만으로 객관적인 문학적 우열을 확정하지 않습니다. 두 심판의 표본 수가 달라 주 순위에 무작정 합치지 않고 따로 보여줄 예정입니다.

추가 <span class="term" data-tip="소프트웨어가 다른 소프트웨어의 기능이나 데이터에 접근할 때 따르는 호출 계약. 사용할 주소, 입력 형식, 인증, 응답과 오류 규칙을 함께 정의한다.">API</span> 예산은 최대 $15, 기존 작업을 포함한 누적 상한은 $55입니다. 원고 수정 단계의 확인 비용은 $8.790255입니다. 실패·잘린 응답도 포함합니다. 실제 사용액과 비용을 확인하지 못한 호출의 예약액을 함께 계산해 요청 전에 한도를 검사합니다. 아직 새 학습본의 평가 결과는 없습니다.

## 7. 이름 분류 오류를 찾아 학습을 멈추고 다시 시작했습니다

검증용 사례를 원문과 대조하다가 인물 목록에 들어간 `Biscuit`이 반려동물 이름이 아니라 간식이라는 것을 발견했습니다. 같은 문제가 학습 원고에도 있는지 조사하니, 두드리는 소리 `Pat, pat`, 종소리 `Ling`, 움직임을 뜻하는 `Bob`, 형용사 `Sandy`가 인물 이름으로 분류된 사례가 있었습니다. 알려진 이름 목록에 있는 단어라고 해서 해당 문맥에서도 이름인 것은 아니었습니다.

이 상태로 이름을 유지하라고 학습하면 실제 인물과 소리를 혼동하는 신호를 줄 수 있습니다. 진행 중이던 로컬 학습을 중단하고, 해당 문맥을 읽어 이름 제외 규칙을 16개 사례에 적용했습니다. 실제 개와 고양이의 이름인 `Biscuit`은 유지했습니다. 검증용 원고에서 누락된 `Tully`, `Scratch`, `Clatter`는 인물 목록에 보완했습니다.

가족 관계도 `auntie`와 `granny` 같은 별칭을 빠뜨리지 않도록 수정했습니다. 배우자 `wife`가 등장하는 검증 원고에 가족 관계가 없다고 표시한 오류도 바로잡았습니다. 이름·관계 정보가 달라진 사례는 학습·검증을 합쳐 21개입니다. 정답 원고와 32편의 이름 치환 결과는 바꾸지 않았습니다.

고유명사 집계 수정 후 학습 원고의 평균 NDL 포함률은 85.3%입니다. 앞 절의 85.4%는 수정 전 집계로 남겼습니다. 수치가 조금 달라진 이유는 원고의 품질 변화가 아니라 제외한 단어의 범위가 바뀌었기 때문입니다. 중단 로그와 이전 데이터는 별도 보관하고, 수정한 데이터로 기반 모델에서 다시 학습을 시작했습니다. 추가 API 호출은 하지 않았습니다.
