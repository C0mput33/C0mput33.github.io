북끼끼의 영어동화 원고를 더 잘 쓰게 하려고 <span class="term" data-tip="총 파라미터 약 35B 중 토큰마다 약 3B를 선택하는 MoE 구조. 전체 가중치 메모리는 필요하며 실제 속도는 라우팅·메모리 대역폭·커널·캐시에 따라 달라진다.">Qwen3.6-35B-A3B</span>를 재학습했습니다. 학습용 원고를 302편으로 늘리고 새 문제 60개에서 비교하니 제목·분량·문단 등 형식 검사 통과는 0편에서 24편으로 늘었습니다. 자동 심판도 학습 후 원고를 더 많이 골랐습니다. 다만 원고의 사건이 반복되거나 어른이 맡아야 할 행동을 아이에게 넘기는 오류가 남아 운영 도입은 보류했습니다.

이 글은 2026년 10월 29일 완료한 로컬 실험 기록입니다. 데이터 생성과 학습, 평가 실행은 코딩 에이전트로 진행했습니다. 아래에서 전문 재검토라고 부르는 단계도 에이전트가 원문을 대조한 것입니다. 사람 편집자나 학부모의 평가를 받은 결과는 아닙니다. 비교 수치와 설정은 [실험 기록 JSON](/assets/data/experiments/qwen-story-sft-20261029/measurements.json)에 함께 남겼습니다.

후속 실험에서는 Astra·Fable 원고 300편으로 새로 학습했습니다. [같은 평가앱에서 교사·학습 전·학습 후를 비교한 기록]({% post_url 2026-10-29-qwen-astra-fable-distillation-arena %})에 결과를 별도로 남겼습니다. 아래는 기존 DeepSeek·Kimi 원고로 실행한 실험입니다.

## 1. 학습 목표와 비교 범위

[앞선 모델 선택 글]({% post_url 2026-07-23-storybook-llm-cost-performance-serving-decision %})에서는 자체 서빙을 품질·성공률·처리시간을 모두 확인한 뒤 선택할 경로로 남겨 두었습니다. 이번에는 그중 원고 품질을 학습으로 개선할 수 있는지 확인했습니다.

짧은 단어나 문장을 쓰는 것만으로는 부족합니다. 아이가 겪은 일을 보존하면서 사건이 이어져야 하고 마지막 장면이 앞에서 생긴 문제를 마무리해야 합니다. 영어가 매끄러워도 중간에 물건의 주인이 바뀌거나 이미 끝난 일을 다시 시작하면 책으로 쓰기 어렵습니다.

실험 범위는 6~8세 아이와 어른이 함께 읽을 영어 원고로 좁혔습니다. 제목을 제외한 180~230단어, 여섯 문단, 현재형 서술을 요청했습니다. 이는 작성 조건입니다. <span class="term" data-tip="영어 독자의 읽기 능력과 텍스트 난이도를 같은 척도에 표시하는 상용 지표. 텍스트 측정은 어휘의 빈도와 문장 길이 같은 특성을 사용하며, 이 프로젝트의 가독성 공식 합성값은 공인 Lexile이 아니다.">Lexile</span>·AR·CEFR 인증 수준이나 아이의 실제 읽기 능력을 측정한 값은 아닙니다.

처음 계획은 좋은 완성 원고를 배우는 <span class="term" data-tip="Supervised Fine-Tuning. 입력과 목표 응답 쌍을 주고 다음 토큰 손실을 줄이도록 모델을 추가 학습하는 단계. 선호쌍을 비교하는 DPO와 데이터 형식과 목적이 다르다.">SFT</span>, 자주 실패하는 부분의 보완 학습, 더 나은 원고를 고르는 <span class="term" data-tip="Direct Preference Optimization. 선택된 응답과 거절된 응답의 선호쌍으로 정책을 최적화하는 학습법. 평가 판정 기록은 품질·정책 버전·누수 여부를 검증한 뒤에만 학습 후보 데이터가 된다.">DPO</span> 순서였습니다. 이번 2차 실험에서는 SFT와 보완 후보까지 실행했습니다. 선호 데이터의 신뢰성을 확인하기 전이어서 DPO는 추가하지 않았습니다.

## 2. 학습 데이터 구성

### 2-1. 입력과 완성 원고를 한 쌍으로 저장

기존 동화책의 본문만 모으면 어떤 요청에서 그 원고가 나왔는지 알 수 없습니다. 그래서 이야기 소재, 반드시 지킬 사실, 결말, 안전 조건을 입력에 넣고 완성 원고를 목표 응답으로 붙였습니다.

아래는 실제 채택 원고 한 편에서 입력 필드와 목표 응답의 첫 문단을 발췌한 예시입니다. 원본 `text`에는 제목과 여섯 문단 전체가 들어 있습니다.

```json
{
  "case": {
    "id": "v2-extra-train-37-2",
    "brief": "Grandmother sends Pri a small wooden box. Pri finds a hidden latch underneath and presses it. The lid opens with a soft click. Inside are coconut sweets. She shows her mother how the latch works.",
    "facts": [
      "Pri receives a small wooden box from her grandmother",
      "She discovers a hidden latch underneath and presses it",
      "The lid opens, revealing coconut sweets inside",
      "Pri shows her mother how to open the box"
    ],
    "structure": "Sensory exploration with intergenerational object, quiet revelation rather than struggle",
    "care": "No tools, heat, or hazards; object is a simple wooden box with a child-safe latch; coconut smell replaced with visible coconut sweets for concrete outcome"
  },
  "text": "The Little Wooden Box\n\nA small parcel arrives for Pri. It is wrapped in brown paper and tied with string. Her mother reads the tag. It says, “For Pri, from Grandmother.” Pri peels the paper back carefully."
}
```

합성 지시 데이터를 만들고 부적절하거나 유사한 사례를 걸러 학습하는 Self-Instruct의 접근을 참고했습니다.[^self-instruct] 다만 이 논문이 북끼끼 동화의 품질 향상을 보장하는 것은 아닙니다. 생성된 정답을 검증하는 과정은 별도로 필요했습니다.

### 2-2. 교사 모델과 실제 채택한 소재

교사 호출에는 <span class="term" data-tip="여러 회사의 LLM을 하나의 API와 결제로 호출하게 해주는 중계 서비스. 모델마다 계정을 따로 만들 필요가 없어 다모델 비교 실험에 편하다.">OpenRouter</span>를 사용했습니다. 학습 정답을 만드는 요청에는 `enforce_distillable_text: true`를 넣어 모델 저자가 텍스트 <span class="term" data-tip="큰 모델의 동작을 더 작거나 빠른 모델에 옮겨 담는 학습 기법. 원 모델의 출력이나 중간 표현을 학생 모델의 학습 신호로 쓴다.">증류</span>를 허용한 모델로 라우팅하도록 했습니다.[^routing] 원문 자료의 이용 조건은 별도로 기록했습니다. <span class="term" data-tip="들어온 요청을 여러 서버·모델·공급자 후보 중 하나로 보내는 선택 과정. 가용성, 현재 부하, 비용, 캐시 재사용 가능성처럼 목적에 맞는 기준과 실패 시 대체 경로가 필요하다.">라우팅</span> 옵션 하나로 원저작물의 권리까지 해결되는 것은 아닙니다.

최종 학습 원고는 DeepSeek V4 Pro 0813에서 나온 152편과 Kimi K2.6에서 나온 150편입니다. 한 모델을 최고 품질이라고 전제하기보다 다른 모델 계열의 검토를 붙여 사실 보존과 문장의 자연스러움을 확인했습니다. 실사용자 인터뷰나 아이의 개인정보는 사용하지 않았습니다.

| 학습 원고 구성 | 편수 |
|---|---:|
| 창작 동화 | 138 |
| 가상 아이 경험 | 111 |
| 가상 일기 | 48 |
| 고전 각색 | 2 |
| 상호작용 장면 | 2 |
| 공개 원문 리라이트 | 1 |
| 합계 | 302 |

고전과 공개 원문도 검토했지만 실제 채택 비중은 작았습니다. 이번 모델을 유명 영어 그림책을 대량으로 학습한 모델이라고 설명하면 맞지 않습니다. 대부분은 가상의 일상과 창작 상황을 바탕으로 만든 합성 데이터입니다.

### 2-3. 학습·검증·최종 시험 분리

학습에는 302편, 중간 학습 가중치 선택용 검증에는 25편을 사용했습니다. 최종 비교 문제 60개는 따로 만들었습니다. 같은 원작의 각색이 학습과 검증 양쪽에 남지 않도록 작품 단위로 나눴습니다. 학습 전에 7편을 검증용으로 옮길 때도 이 기준을 지켰습니다.

이름을 제외한 어휘 유사도와 n-gram 겹침도 검사했습니다. 이름만 바꾼 이야기를 다른 데이터처럼 세지 않기 위해서입니다. 이 검사로 모든 의미적 중복이 사라졌다고 보지는 않습니다. 새 시험 문제라는 표현도 이번 미세조정에 쓰지 않았다는 의미이며 기반 모델의 사전학습에서 고전 원전을 본 적이 없다는 뜻은 아닙니다.

## 3. 자동 검수를 통과한 원고를 다시 확인한 이유

후보 원고에는 사실 보존·문학성 평가와 다른 모델 계열의 추가 검토를 붙였습니다. 그런데 자동 통과 기록과 실제 글이 맞지 않는 경우가 있었습니다.

| 대조한 사례 | 확인한 문제 | 처리 |
|---|---|---|
| 양말을 서로 바꾸는 이야기 | 양말 한 개씩만 바꿨는데 둘 다 한 켤레를 얻음 | 제외 |
| 액자를 만드는 이야기 | 유리가 있는 액자 안의 종이에 압정을 관통시킴 | 제외 |
| 운율을 맞춘 원고 | 문장 형식은 맞지만 영어 표현이 부자연스러움 | 제외 |
| 책갈피를 만드는 이야기 | 테이프로 책갈피 가장자리를 붙인 것을 책에 고정했다고 심판이 해석 | 원문 대조 후 오판 수정 |
| 신발 이야기 | 신발 앞코를 뜻한 toes를 아이의 맨발 발가락으로 해석 | 원문 대조 후 오판 수정 |

평가기의 지적을 그대로 모두 받아들이면 정상 원고도 버리게 됩니다. 반대로 통과 점수만 믿으면 수량이나 물체 상태가 틀린 원고가 정답으로 들어갑니다. 그래서 판정 이유를 실제 문장과 대조했습니다.

이 과정에서 후보 기록 238편에 에이전트의 전문 검토 근거를 남겼습니다. 그중 최종 학습·검증 327편에 포함된 원고는 117편입니다. 모든 채택 원고를 사람이 읽고 승인한 상태는 아닙니다.

학습을 시작한 뒤에도 추가 표본을 읽다가 기존 채택 원고 6편의 상태·안전 문제를 찾았습니다. 첫 학습을 중단하고 6편을 제외한 뒤 다른 7편을 채택했습니다. 이렇게 확정한 302편으로 다시 시작했습니다. 수정 전 중간 학습 가중치는 보존했지만 최종 후보에서는 뺐습니다.

검수를 통과한 파일을 고정해야 어떤 데이터로 나온 결과인지 설명할 수 있습니다. 학습·검증 파일, 시험 문제와 선택한 <span class="term" data-tip="동결한 베이스 모델 옆에 붙여 학습하는 작은 추가 가중치 묶음. 파일이 작아도 층 이름과 배열 모양이 실행 프레임워크의 형식과 맞지 않으면 그대로 옮겨 쓸 수 없다.">어댑터</span>의 해시를 남긴 이유도 같습니다.

## 4. 학습 설정에서 놓친 혼합 attention 구조

### 4-1. 여덟 층으로 설정했지만 실제로는 두 층만 학습

학습은 M5 Pro, <span class="term" data-tip="애플 실리콘에서 CPU와 GPU가 같은 물리 메모리 풀을 공유하는 구조. 별도 VRAM으로 복사하는 비용을 줄일 수 있지만 운영체제와 다른 프로세스가 쓰는 몫까지 고려해야 한다.">통합 메모리</span> 48GB인 Mac에서 <span class="term" data-tip="Apple이 애플 실리콘용으로 만든 배열·머신러닝 프레임워크. CPU와 GPU가 공유하는 통합 메모리 모델을 사용하며 추론과 학습을 지원한다.">MLX</span> <span class="term" data-tip="원본 가중치는 얼려 두고 곁에 붙인 작은 저랭크 행렬(어댑터)만 학습하는 파인튜닝 기법. 학습 대상이 전체의 1% 미만이라 메모리와 시간이 크게 줄고, 어댑터만 따로 저장·교체할 수 있다.">LoRA</span>로 실행했습니다. 원본 가중치를 고정하고 작은 추가 행렬을 학습하는 방식입니다.[^lora] 사용한 기반 모델은 MLX affine 4bit 변환본입니다. NF4를 사용하는 <span class="term" data-tip="동결한 사전학습 모델을 4비트로 저장하고 그 위에 LoRA 어댑터만 학습하는 파인튜닝 방법. 원 논문은 NF4·double quantization·paged optimizer를 함께 사용해 메모리를 줄였다.">QLoRA</span> 구성이나 AWS <span class="term" data-tip="오픈소스 LLM 추론·서빙 엔진. PagedAttention과 연속 배칭 같은 기법으로 KV 캐시와 동시 요청을 관리하며 OpenAI 호환 서버를 제공한다.">vLLM</span> 실험으로 설명하지 않았습니다.

첫 설정은 마지막 여덟 층의 `self_attn.q_proj`, `self_attn.v_proj`를 대상으로 했습니다. 저장된 어댑터의 실제 키를 열어 보니 다음 두 층만 있었습니다.

```text
language_model.model.layers.35.self_attn.q_proj.lora_a
language_model.model.layers.35.self_attn.v_proj.lora_a
language_model.model.layers.39.self_attn.q_proj.lora_a
language_model.model.layers.39.self_attn.v_proj.lora_a
```

나머지 여섯 층은 `linear_attn` 계열이어서 지정한 이름에 걸리지 않았습니다. `num_layers: 8`이라는 설정값만 확인해서는 실제 학습 범위를 알 수 없었습니다.

새 후보에서는 일반 attention과 <span class="term" data-tip="어텐션 계산을 시퀀스 길이에 비례(선형)하도록 근사하는 방식. 긴 문맥에서 메모리와 속도가 유리해 최신 하이브리드 모델이 다수 층에 채택하지만, 표준 어텐션과 구현이 달라 학습·서빙 도구의 지원 여부를 따로 확인해야 한다.">linear attention</span>의 투영 행렬을 함께 지정했습니다. 학습을 시작하기 전에 32~39번 여덟 층에 어댑터가 붙었는지 확인했습니다. 실제 학습 파라미터는 6,500,352개였습니다. 두 층만 학습한 것이 모든 원고 오류의 원인이라고 단정하지는 않았습니다.
