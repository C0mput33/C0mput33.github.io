13개 모델이 동화 한 권을 생성할 때 발생한 <span class="term" data-tip="오픈라우터가 모든 응답의 usage 객체에 실어주는 실제 청구 금액(usage.cost). 토큰 수에 단가를 곱해 추정하는 것이 아니라 계정에서 실제로 빠져나간 크레딧이다.">실청구액</span>을 비교했다. 공개 단가를 곱해 끝내지 않고 <span class="term" data-tip="여러 회사의 LLM을 하나의 API와 결제로 호출하게 해주는 중계 서비스. 모델마다 계정을 따로 만들 필요가 없어 다모델 비교 실험에 편하다.">OpenRouter</span>의 `usage.cost`를 썼다. 프롬프트 길이, 추론 <span class="term" data-tip="모델의 토크나이저가 텍스트를 나눈 처리 단위. 한 토큰은 단어 하나와 같지 않으며 같은 문장도 모델별 토크나이저에 따라 토큰 수가 달라질 수 있다.">토큰</span>, 실제 라우팅된 공급자에 따라 모델별 비용이 달라질 수 있어서다.

## 데이터는 이미 있었다

[5편](/posts/46-dollar-frontier-live-eval-13-models/)의 797쌍 실측 때 앱은 이미 생성 콜마다 청구액을 기록하고 있었다. 오픈라우터는 모든 응답의 `usage`에 토큰 수와 실제 청구 금액을 함께 실어 준다.[^ua] 앱은 생성 콜 직전과 직후 누적값의 차이를 모델별로 쌓아 뒀다(`state.modelCost`). 범위는 모델당 10~13권이고, 짧은 동화(평균 181~230단어)의 텍스트 생성만 들어 있다. 새 <span class="term" data-tip="소프트웨어가 다른 소프트웨어의 기능이나 데이터에 접근할 때 따르는 호출 계약. 사용할 주소, 입력 형식, 인증, 응답과 오류 규칙을 함께 정의한다.">API</span> 호출을 새로 하지 않고 <span class="term" data-tip="진행 상태를 통째로 저장해둔 지점. 중단되거나 크레딧이 떨어져도 완료분을 다시 호출하지 않고 그 지점부터 이어서 실행할 수 있다.">체크포인트</span>만 다시 읽으면 됐다.[^ckpt]

가장 싼 gemma-4-31b와 가장 비싼 gemini-3.1-pro는 240배 차이가 난다. 로컬로 돌린 모델(gemma4-e4b, <span class="term" data-tip="오픈 웨이트 모델을 로컬 장비에서 내려받아 실행하고 API로 호출하게 해주는 도구. 외부 모델 API의 호출 요금은 없지만 장비·전력·운영 비용은 별도다.">Ollama</span>)은 과금이 없어 표에서 뺐다.

단어 수와 비용은 따로 놀았다. qwen3.5-122b는 201단어짜리 동화 한 편에 4,505토큰을 썼다. 눈에 보이는 글자는 300토큰이 안 되고 나머지는 <span class="term" data-tip="일부 추론 모델이 최종 답을 내기 전에 사용하는 내부 계산 토큰으로 API usage에 별도 집계될 수 있다. 과금 포함 여부와 단가는 모델·공급자 정책을 확인해야 한다.">추론 토큰</span>이다. 반대로 gpt-5.2는 권당 430토큰으로 끝냈다. 짧은 창작 작업에서는 토큰 단가표보다 그 모델이 사고에 토큰을 얼마나 쓰는지가 권당 원가를 정했다. 비용을 토큰당이 아니라 권당으로 계산한 이유다. 단가가 3배 싼 모델도 토큰을 10배 쓰면 더 비싸다.

## 이 숫자를 믿어도 되나: 단가표와 교차 검증

청구액이 1차 수치이긴 해도 검증 없이 싣지는 않기로 했다. 2026-07-19의 오픈라우터 공개 단가표[^models]로 각 모델의 권당 비용을 재계산해 청구액과 비교했다. 입력 토큰은 실제 프롬프트 문자 수를 4로 나눈 근사값을 썼다(모델별 토크나이저 차이로 ±15% 안팎 오차 가능).[^approx] 12개 중 9개가 청구액과 ±10% 안에서 맞았다.

벗어난 3개에서 오히려 배울 게 있었다. 오픈라우터는 한 모델을 여러 공급자로 나눠 라우팅하고,[^route] 공급자마다 단가가 다르다. gemma-4-31b의 공급자별 단가는 입력 $0.10~0.99/M까지 퍼져 있는데, 최저가 공급자($0.10/$0.35) 기준으로 다시 계산하면 권당 $0.000102가 나와 청구액 $0.000109와 거의 같다. glm-5.2는 반대였다. 지금 보이는 헤드라인 단가($0.279/$0.876)는 실측 뒤에 나온 최저가다. 실측 당시 다수 공급자 티어($1.40/$4.40)로 계산하니 청구액과 맞았다. 같은 모델, 같은 표시 단가라도 <span class="term" data-tip="들어온 요청을 여러 서버·모델·공급자 후보 중 하나로 보내는 선택 과정. 가용성, 현재 부하, 비용, 캐시 재사용 가능성처럼 목적에 맞는 기준과 실패 시 대체 경로가 필요하다.">라우팅</span>에 따라 실효 단가가 달라진다. 비용을 고정하려면 공급자를 지정하거나 단가 상한을 걸어야 한다.

## 캐시 히트가 0이었던 이유

캐시 히트레이트도 재려 했지만 기존 실측으로는 잴 수 없었다. 이유는 두 겹이다.

먼저 앱이 `cached_tokens`를 기록하지 않았다. 이건 앱에서 캐시 토큰을 누적해 보여 주도록 고쳐서 해결했다.

그런데 기록했더라도 당시 프롬프트로는 0이 나왔을 가능성이 높다.
<span class="term" data-tip="반복되는 프롬프트 앞부분의 계산 결과를 재사용해 지연이나 입력 비용을 줄이는 기능. 자동·명시형 여부, 최소 길이, 만료 시간, 할인율은 모델과 공급자마다 다르다.">프롬프트 캐싱</span>에는 공급자별 최소 <span class="term" data-tip="프롬프트의 앞부분에 반복해서 붙는 공통 입력 구간. 프롬프트 캐시는 이 구간이 같고 공급자의 최소 길이·라우팅 조건을 충족할 때 재사용될 수 있다.">프리픽스</span> 길이가 있다.
OpenAI는 1,024토큰부터 자동 적용한다.[^cacheO]
Claude는 모델에 따라 1,024 또는 2,048토큰, Gemini 3.1 Pro와 3.5 Flash는 4,096토큰부터다.[^cacheA][^cacheG]
평가용 생성 프롬프트는 약 172토큰이라 어느 기준도 넘지 못했다.

그래서 프로덕션용 생성 프롬프트를 새로 짜면서 캐시를 조건에 넣었다. 정적부(작법 규칙, 연령 밴드별 언어 규칙, 페이지/삽화 규칙, <span class="term" data-tip="문자열·숫자·불리언·배열·객체·null을 표현하는 텍스트 데이터 형식. 주석과 trailing comma는 표준 JSON에 포함되지 않는다.">JSON</span> 스키마, 투샷 예제)를 1.3~1.5K토큰으로 키우고, 유저 메시지에서는 가변부(아이 정보, 인터뷰 요약)만 갈아 끼운다. 이러면 OpenAI 계열과 Opus 4.8은 캐시 사정권에 들어온다. Opus 4.7(2,048)과 Gemini(4,096)는 여전히 모자라서, 예제를 늘린 v2로 갈지는 실측을 보고 정한다. 새 프롬프트 기준 권당 단가와 <span class="term" data-tip="캐시 조회 또는 재사용 대상 중 실제 캐시에서 처리된 비율. 토큰·블록·요청 중 무엇을 분모로 삼는지는 구현마다 달라 같은 이름의 수치를 바로 비교하면 안 된다.">캐시 히트율</span>은 측정 스크립트로 잰다. 위 표는 200단어급 짧은 동화 기준이라서, 25페이지 프로덕션 기준 절대액은 실측으로만 확정할 생각이다. 추정치를 표로 싣지 않는 것이 이 시리즈의 원칙이다.

## 남은 것

프롬프트·분석 스크립트·단가 스냅샷·리포트는 저장소에 올렸다.[^repo] 다만 저장소가 아직 비공개라서 남이 재현해 볼 수는 없다. 다음 작업은 두 가지다. 새 프롬프트로 모델당 10권을 실제로 생성하면서 캐시 전후 차이와 25페이지 기준 권당 단가를 확정한다. 그다음 품질 점수와 붙여서 합격선을 넘는 모델 가운데 가장 싼 쪽을 고른다. gemma-4-31b는 이 표에서 비용이 가장 낮지만 5편의 레거시 품질 순위에서는 하위권이었다. 최저가 모델이 아니라, 품질 허용선을 통과한 후보 중 비용이 낮은 모델을 찾아야 한다.
