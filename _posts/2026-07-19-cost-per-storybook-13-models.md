동화 생성 모델을 고르려면 품질과 함께 한 권당 원가를 알아야 합니다. 13개 모델의 실제 청구액으로 계산해보니 한 권 원가가 모델마다 최대 240배 차이가 났습니다. 아래에서는 원가를 어떻게 계산했는지, 차이를 만든 원인이 무엇인지, 캐시가 왜 전혀 걸리지 않았는지를 정리했습니다.

같은 모델이라도 프롬프트 길이, 추론 <span class="term" data-tip="모델의 토크나이저가 텍스트를 나눈 처리 단위. 한 토큰은 단어 하나와 같지 않으며 같은 문장도 모델별 토크나이저에 따라 토큰 수가 달라질 수 있다.">토큰</span>, 그날 라우팅된 공급자에 따라 청구액이 달라집니다. 그래서 공개 단가에 토큰 수를 곱하지 않고, <span class="term" data-tip="여러 회사의 LLM을 하나의 API와 결제로 호출하게 해주는 중계 서비스. 모델마다 계정을 따로 만들 필요가 없어 다모델 비교 실험에 편하다.">OpenRouter</span>가 돌려준 `usage.cost`, 즉 <span class="term" data-tip="오픈라우터가 모든 응답의 usage 객체에 실어주는 실제 청구 금액(usage.cost). 토큰 수에 단가를 곱해 추정하는 것이 아니라 계정에서 실제로 빠져나간 크레딧이다.">실청구액</span>을 그대로 사용했습니다.

## 1. 데이터 수집 방법

새로 생성을 돌릴 필요는 없었습니다. [5편](/posts/46-dollar-frontier-live-eval-13-models/)에서 797쌍을 실측할 때 앱이 생성 콜마다 청구액을 기록해 두었기 때문입니다. 오픈라우터는 모든 응답의 `usage`에 토큰 수와 실제 청구 금액을 함께 담아 줍니다.[^ua] 앱은 생성 콜 직전과 직후의 누적값 차이를 모델별로 쌓아 두었습니다(`state.modelCost`).

대상은 모델당 10~13권, 평균 181~230단어짜리 짧은 동화의 텍스트 생성분입니다. <span class="term" data-tip="소프트웨어가 다른 소프트웨어의 기능이나 데이터에 접근할 때 따르는 호출 계약. 사용할 주소, 입력 형식, 인증, 응답과 오류 규칙을 함께 정의한다.">API</span>는 새로 호출하지 않았고 <span class="term" data-tip="진행 상태를 통째로 저장해둔 지점. 중단되거나 크레딧이 떨어져도 완료분을 다시 호출하지 않고 그 지점부터 이어서 실행할 수 있다.">체크포인트</span>만 다시 읽었습니다.[^ckpt]

## 2. 모델별 권당 원가

한 권 원가는 $0.0001에서 $0.026까지 퍼져 있었습니다. 모델별 결과는 다음과 같습니다.

가장 싼 gemma-4-31b와 가장 비싼 gemini-3.1-pro의 차이는 240배입니다. 로컬로 돌린 gemma4-e4b(<span class="term" data-tip="오픈 웨이트 모델을 로컬 장비에서 내려받아 실행하고 API로 호출하게 해주는 도구. 외부 모델 API의 호출 요금은 없지만 장비·전력·운영 비용은 별도다.">Ollama</span>)는 과금이 없어서 표에서 뺐습니다.

표에서 먼저 보이는 것은 단어 수와 비용이 거의 따로 움직인다는 점입니다. qwen3.5-122b는 201단어짜리 동화 한 편에 4,505토큰을 썼습니다. 화면에 출력된 글은 300토큰도 되지 않고, 나머지는 모두 <span class="term" data-tip="일부 추론 모델이 최종 답을 내기 전에 사용하는 내부 계산 토큰으로 API usage에 별도 집계될 수 있다. 과금 포함 여부와 단가는 모델·공급자 정책을 확인해야 한다.">추론 토큰</span>입니다. 비슷한 길이를 쓴 gpt-5.2는 430토큰에서 끝났습니다.

짧은 창작에서는 단가표보다 모델이 추론에 토큰을 얼마나 쓰는지가 원가를 결정했습니다. 단가가 3배 싼 모델도 토큰을 10배 쓰면 더 비쌉니다. 비용을 토큰당이 아니라 권당으로 계산한 이유도 여기에 있습니다.

## 3. 단가표 교차 검증

청구액이 1차 수치이긴 하지만, 검증 없이 싣지 않기로 했습니다. 2026-07-19 오픈라우터 공개 단가표[^models]로 모델별 권당 비용을 다시 계산해서 청구액과 비교했습니다. 입력 토큰은 실제 프롬프트 문자 수를 4로 나눈 근사값입니다(토크나이저 차이로 ±15% 안팎 오차가 날 수 있습니다).[^approx] 12개 중 9개가 ±10% 안에서 일치했습니다.

어긋난 3개는 공급자 때문이었습니다. 오픈라우터는 한 모델을 여러 공급자로 나눠 라우팅하고,[^route] 공급자마다 단가가 다릅니다.

gemma-4-31b는 공급자별 입력 단가가 $0.10~0.99/M까지 퍼져 있습니다. 최저가 공급자($0.10/$0.35)로 다시 계산하니 권당 $0.000102가 나왔고, 청구액 $0.000109와 거의 같았습니다.

glm-5.2는 반대였습니다. 지금 화면에 보이는 단가($0.279/$0.876)는 실측이 끝난 뒤에 생긴 최저가였습니다. 실측 당시 다수 공급자 티어($1.40/$4.40)로 계산해야 청구액과 맞았습니다. 표시 단가만 보고 예산을 잡으면 <span class="term" data-tip="들어온 요청을 여러 서버·모델·공급자 후보 중 하나로 보내는 선택 과정. 가용성, 현재 부하, 비용, 캐시 재사용 가능성처럼 목적에 맞는 기준과 실패 시 대체 경로가 필요하다.">라우팅</span> 한 번에 어긋날 수 있다는 뜻입니다. 비용을 고정하려면 공급자를 지정하거나 단가 상한을 걸어야 합니다.

## 4. 캐시 히트가 0이었던 이유

캐시 히트레이트도 측정하려고 했지만 기존 실측 데이터로는 불가능했습니다. 막힌 곳은 두 군데였습니다.

첫째, 앱이 `cached_tokens`를 기록하지 않았습니다. 이 부분은 앱에서 캐시 토큰을 누적해 보여 주도록 수정했습니다.

둘째가 더 근본적인 원인입니다. 기록을 했더라도 당시 프롬프트로는 0이 나왔을 가능성이 높습니다. <span class="term" data-tip="반복되는 프롬프트 앞부분의 계산 결과를 재사용해 지연이나 입력 비용을 줄이는 기능. 자동·명시형 여부, 최소 길이, 만료 시간, 할인율은 모델과 공급자마다 다르다.">프롬프트 캐싱</span>에는 공급자마다 최소 <span class="term" data-tip="프롬프트의 앞부분에 반복해서 붙는 공통 입력 구간. 프롬프트 캐시는 이 구간이 같고 공급자의 최소 길이·라우팅 조건을 충족할 때 재사용될 수 있다.">프리픽스</span> 길이가 있습니다.

- OpenAI: 1,024토큰부터 자동 적용[^cacheO]
- Claude: 모델에 따라 1,024 또는 2,048토큰부터[^cacheA]
- Gemini 3.1 Pro와 3.5 Flash: 4,096토큰부터[^cacheG]

평가용 생성 프롬프트는 172토큰 정도라 어느 기준에도 미치지 못했습니다.

그래서 프로덕션용 생성 프롬프트를 새로 작성할 때는 이 길이를 처음부터 조건으로 넣었습니다. 작법 규칙, 연령 밴드별 언어 규칙, 페이지/삽화 규칙, <span class="term" data-tip="문자열·숫자·불리언·배열·객체·null을 표현하는 텍스트 데이터 형식. 주석과 trailing comma는 표준 JSON에 포함되지 않는다.">JSON</span> 스키마, 투샷 예제를 정적부로 묶어 1.3~1.5K토큰까지 늘렸습니다. 유저 메시지에서는 아이 정보와 인터뷰 요약 같은 가변부만 바꿔 넣습니다. 이 정도면 OpenAI 계열과 Opus 4.8은 캐시 대상에 들어갑니다. Opus 4.7(2,048)과 Gemini(4,096)에는 아직 부족합니다. 예제를 더 늘린 v2로 갈지는 실측 결과를 보고 정할 계획입니다.

새 프롬프트의 권당 단가와 <span class="term" data-tip="캐시 조회 또는 재사용 대상 중 실제 캐시에서 처리된 비율. 토큰·블록·요청 중 무엇을 분모로 삼는지는 구현마다 달라 같은 이름의 수치를 바로 비교하면 안 된다.">캐시 히트율</span>은 측정 스크립트로 잽니다. 위 표는 200단어급 짧은 동화 기준이라 25페이지짜리 실제 책 원가와는 다릅니다. 그 금액은 추정치로 싣지 않고, 실측이 나오면 따로 적겠습니다.

## 마치며

13개 모델의 한 권 원가는 최대 240배 차이가 났고, 그 차이는 글자 수보다 추론 토큰에서 나왔습니다. 공개 단가표는 라우팅되는 공급자에 따라 실제 청구액과 어긋날 수 있다는 점도 확인했습니다.

프롬프트, 분석 스크립트, 단가 스냅샷, 리포트는 저장소에 올렸습니다.[^repo] 다만 저장소가 아직 비공개라 다른 사람이 재현해볼 수는 없습니다.

다음에는 새 프롬프트로 모델당 10권을 실제로 생성해서 캐시 전후 차이와 25페이지 기준 권당 단가를 확정할 계획입니다. 그 숫자를 품질 점수 옆에 놓고, 합격선을 넘긴 모델 중 가장 싼 모델을 고르려고 합니다. 참고로 이 표의 최저가인 gemma-4-31b는 5편의 레거시 품질 순위에서 하위권이었습니다.
