Astra 160편과 Fable 140편의 영어동화 원고로 <span class="term" data-tip="총 파라미터 약 35B 중 토큰마다 약 3B를 선택하는 MoE 구조. 전체 가중치 메모리는 필요하며 실제 속도는 라우팅·메모리 대역폭·커널·캐시에 따라 달라진다.">Qwen3.6-35B-A3B</span>를 다시 학습했습니다. 자동 비교만으로 새 학습본이 학습 전보다 일관되게 좋아졌다고 결론 내리지 못했습니다. 24개 문제의 직접 비교는 새 학습본 10승, 학습 전 15승, 평균 동점 19건입니다. 별도로 고정한 12개 문제에서는 새 학습본 10승, 학습 전 5승, 평균 동점 9건이 나왔습니다. 한 문제에 심판 두 개가 각각 판정하며, 순서 교환 결과가 뒤집힌 경우도 평균 동점에 포함됩니다.

이 글은 2026년 10월 29일 로컬 실험의 기록입니다. 생성·검토·학습·평가는 코딩 에이전트로 실행했습니다. 사람 편집자나 실제 아동의 평가 결과가 아니며 운영 앱에는 연결하지 않았습니다.

후속 점검에서는 같은 어댑터의 기여와 생성 설정을 바꿨습니다. 새 24문제에서 수정 후보의 상대 점수는 가장 높았지만, 이름·관계 오류가 남아 운영 모델로 채택하지 않았습니다. 9절부터 원인 분석과 평가앱 수정, 새 비교 결과를 이어 기록했습니다.

[설정과 실측 JSON](/assets/data/experiments/qwen-frontier-teachers-20261029/measurements.json), [별도 12문제 확인](/assets/data/experiments/qwen-frontier-teachers-20261029/confirmation.json)에 수치를 남겼습니다.

## 1. 교사 모델을 바꾸되 과거 기록은 남겼습니다

[앞선 실험]({% post_url 2026-10-29-qwen-story-sft-302-manuscripts %})에서는 DeepSeek 152편과 Kimi 150편으로 Qwen을 학습했습니다. 그 글의 교사 이름을 Astra와 Fable로 바꾸면 실제로 수행한 실험과 달라집니다. 따라서 기존 결과는 남기고 새 교사 원고로 별도의 학습을 진행했습니다.

이번에 선택한 교사는 <span class="term" data-tip="여러 회사의 LLM을 하나의 API와 결제로 호출하게 해주는 중계 서비스. 모델마다 계정을 따로 만들 필요가 없어 다모델 비교 실험에 편하다.">OpenRouter</span>의 `openai/gpt-6-astra`와 `anthropic/claude-fable-5.1`입니다. 두 모델이 모든 글쓰기에서 가장 좋다고 확정한 것은 아닙니다. 북끼끼의 영어동화 요청에서 이 모델들의 원고를 직접 비교하고, 그 원고를 배운 Qwen의 변화까지 확인하는 것이 목표였습니다.

여기서 <span class="term" data-tip="큰 모델의 동작을 더 작거나 빠른 모델에 옮겨 담는 학습 기법. 원 모델의 출력이나 중간 표현을 학생 모델의 학습 신호로 쓴다.">증류</span>라고 부르는 작업은 교사의 완성 응답을 목표로 삼는 <span class="term" data-tip="Supervised Fine-Tuning. 입력과 목표 응답 쌍을 주고 다음 토큰 손실을 줄이도록 모델을 추가 학습하는 단계. 선호쌍을 비교하는 DPO와 데이터 형식과 목적이 다르다.">SFT</span>입니다. 교사 모델의 가중치나 내부 확률을 가져오지 않았습니다. 새 원고는 기존 학습 <span class="term" data-tip="동결한 베이스 모델 옆에 붙여 학습하는 작은 추가 가중치 묶음. 파일이 작아도 층 이름과 배열 모양이 실행 프레임워크의 형식과 맞지 않으면 그대로 옮겨 쓸 수 없다.">어댑터</span> 위에 이어 학습하지 않고, 같은 Qwen 기반 가중치에서 시작한 별도 어댑터에 사용했습니다.

### 1-1. API 접근과 학습 이용 허가는 다릅니다

처음에는 `enforce_distillable_text: true`로 두 교사 모델을 요청했지만, 기본 증류 허용 경로를 찾지 못했습니다. 생성 <span class="term" data-tip="소프트웨어가 다른 소프트웨어의 기능이나 데이터에 접근할 때 따르는 호출 계약. 사용할 주소, 입력 형식, 인증, 응답과 오류 규칙을 함께 정의한다.">API</span>를 호출할 수 있다는 사실만으로 학습 이용까지 허용됐다고 처리하지 않았습니다. 별도 허가를 확인했다는 프로젝트 소유자의 응답을 받은 뒤, 그 확인을 이번 작업의 이용 근거로 기록했습니다. 계약 원문을 제가 독립적으로 검증한 것은 아닙니다. 이 경로를 모든 사용자가 일반적으로 이용할 수 있다는 의미도 아닙니다.[^routing]

## 2. 기존 원고가 아닌 소재와 조건을 재사용했습니다

기존 데이터에서 이야기 소재, 지킬 사실, 결말, 주의할 행동만 가져왔습니다. DeepSeek나 Kimi가 쓴 기존 완성 원고는 새 교사 요청과 새 학습 목표에 포함하지 않았습니다. 여기에 세탁소, 가족 엽서, 실내 놀이, 박물관 관찰 등 가상의 새 소재를 보탰습니다. 실제 아이의 인터뷰나 개인정보는 보내지 않았습니다.

요청은 평가앱의 현재 생성 규약에 맞췄습니다. 7세 아이와 어른이 함께 읽는 180~230단어의 본문이며 제목과 고정 문단 수는 요구하지 않았습니다. 이전 실험은 제목과 여섯 문단을 요청했으므로 교사만 교체한 통제 실험은 아닙니다. 학습률도 함께 조정했으며, 개선이 있더라도 어느 변경 하나의 효과로 분리할 수 없습니다.

짧은 문장만 많이 쌓으면 모든 이야기가 같은 모양으로 끝나기 쉽습니다. 그래서 작은 문제 해결, 관찰, 조용한 감정 변화, 누적되는 반복, 협동, 순환형 결말을 함께 사용했습니다. 반복 자체를 결함으로 보지 않고 앞선 사건에 어떤 변화를 더하는지 확인했습니다.


최종 학습에는 300편, 검증에는 24편을 사용했습니다. 학습 원고의 구성은 창작 144편, 가상 아이 경험 105편, 가상 일기 47편, 상호작용 장면 2편, 고전 각색 1편, 공개 원문 리라이트 1편입니다. 유명 동화책을 대량으로 학습했다고 설명할 수 있는 구성은 아닙니다. 원문을 사용하는 사례에는 저자·URL·라이선스·각색 여부를 별도로 기록했습니다.

학습 전 후보 39편을 원문 대조했고, 이 중 최종 학습·검증에 들어간 것은 28편입니다. 모든 원고를 사람이 읽고 승인했다는 의미가 아닙니다. 같은 작품 그룹이 학습과 검증에 겹치지 않는지, 목표 텍스트가 중복되지 않는지, 전체 요청과 응답이 잘리지 않는지도 검사했습니다.

## 3. 자동 검토가 정상 표현을 오류로 잡았습니다

원고마다 분량과 출력 형식을 검사하고 Kimi에 사건, 수량, 소유자, 행동, 영어 표현을 검토하도록 요청했습니다. 지적된 문장을 원고에서 찾을 수 있는지 확인하고, 근거가 있는 지적만 수정 요청에 전달했습니다. 통과하지 못한 일부는 다른 교사 모델로 다시 읽었습니다.

그런데 인용이 실제로 존재해도 판단은 틀릴 수 있었습니다. 의인화된 수달 이야기의 “He knelt by the other two stones”를 두고 검토 모델이 수달에게 무릎이 없어 불가능하다고 지적했습니다. 이미 동물들이 사람처럼 행동하는 동화에서 이 문장만 모순으로 처리할 근거는 부족했습니다. 이런 판정을 모두 고치면 원고가 오히려 어색해질 수 있습니다.

반대로 자동 통과 원고에서도 소재의 문제가 보였습니다.

| 사례 | 확인한 점 | 처리 |
|---|---|---|
| 땅에 묻은 무화과와 싹 | 정확히 7일 만에 싹이 난다는 입력의 근거가 확인되지 않음 | 제외 |
| 매주 나타나는 노란 장갑 | 여우에게 장갑이 있다는 결말만으로 반복과 실의 단서가 설명되지 않음 | 제외 |
| 밤마다 짧아지는 연필 | 잘린 실에 대한 아빠의 설명과 잠결에 그리는 동생이 별개로 이어짐 | 제외 |
| 담요 안의 그림자 곰 | 턱 아래 손전등과 벽에 비친 머리 그림자의 배치가 불명료함 | 제외 |
| 문이 삐걱거리는 후렴 | 같은 소리가 네 번 등장하지만 소리의 정체를 알아가는 장면이 진행됨 | 횟수만으로 탈락시키지 않음 |

별도 원문 대조는 코딩 에이전트가 수행했습니다. 사람이 편집하거나 부모와 아이가 평가한 데이터는 아닙니다. 검토 모델의 통과가 사실성이나 연령 적합성을 보증하지 않는다는 한계는 그대로 남습니다.

## 4. 검증 원고로 저장 가중치를 선택했습니다

첫 실행은 <span class="term" data-tip="대량의 수치 연산을 병렬 처리하는 프로세서. LLM에서는 행렬 연산을 빠르게 수행하지만 모델 적재 가능 크기는 연산 성능뿐 아니라 GPU 메모리에도 제한된다.">GPU</span> 메모리 부족으로 첫 업데이트 전에 중단됐습니다. 캐시 한도를 낮춘 두 번째 실행도 같은 지점에서 멈췄습니다. 이번 입력의 최대 길이는 1,203토큰으로 이전 실험의 789토큰보다 길었습니다. 공통 시스템 지시문만 짧게 바꿔 최대 828토큰으로 줄였고, 개별 요청과 완성 원고가 바이트 단위로 그대로인지 확인했습니다. 비교 평가의 요청은 바꾸지 않았습니다. 실패 로그와 변경 전 데이터도 남겼습니다.

축약 후 실행은 진행됐지만 처리 속도가 낮아 초기에 중단했습니다. 캐시 한도를 256MiB에서 2GiB로 조정하고 같은 기반 가중치·데이터·시드로 다시 시작했습니다. 다른 앱이나 사용자의 프로세스는 종료하지 않았습니다. 입력 길이와 캐시 설정을 함께 바꿨으므로 어느 하나가 메모리 실패의 단독 원인이었다고 결론 내리지는 않았습니다.

학습은 기존과 같은 Mac의 <span class="term" data-tip="Apple이 애플 실리콘용으로 만든 배열·머신러닝 프레임워크. CPU와 GPU가 공유하는 통합 메모리 모델을 사용하며 추론과 학습을 지원한다.">MLX</span> <span class="term" data-tip="원본 가중치는 얼려 두고 곁에 붙인 작은 저랭크 행렬(어댑터)만 학습하는 파인튜닝 기법. 학습 대상이 전체의 1% 미만이라 메모리와 시간이 크게 줄고, 어댑터만 따로 저장·교체할 수 있다.">LoRA</span>로 실행했습니다. 4bit Qwen3.6-35B-A3B의 마지막 여덟 층에 있는 일반 attention과 <span class="term" data-tip="어텐션 계산을 시퀀스 길이에 비례(선형)하도록 근사하는 방식. 긴 문맥에서 메모리와 속도가 유리해 최신 하이브리드 모델이 다수 층에 채택하지만, 표준 어텐션과 구현이 달라 학습·서빙 도구의 지원 여부를 따로 확인해야 한다.">linear attention</span>을 모두 포함했습니다. 설정 파일만 확인하지 않고 실제 학습 가능한 텐서의 층 번호도 확인했습니다.[^mlx]

이전 어댑터가 새 요청에서 끝없이 반복한 사례를 보고 학습률을 `3e-5`에서 `1e-5`로 낮췄습니다. 더 작은 업데이트가 반복을 줄일 것이라는 가설이며, 결과가 나오기 전부터 해결됐다고 보지는 않았습니다. 한 차례의 학습을 수행하고 중간 가중치를 저장했습니다.

선택 기준은 검증 원고의 NLL입니다. 학습 로그의 평가 시점과 저장 시점이 다르므로, 로그에 적힌 가장 낮은 숫자를 그대로 선택하지 않고 실제 저장 파일을 다시 불러 점수를 측정했습니다. 비교 문제의 <span class="term" data-tip="이 시스템의 최종 점수. BT로 추정한 실력값을 체스 레이팅처럼 읽히도록 평균 1000 기준으로 변환한 것. 두 모델의 점수 차가 곧 승률로 환산된다(차이 100이면 약 64%, 400이면 약 91%).">Arena 점수</span>로 저장 가중치를 고르지 않았습니다.

실제 학습 가능한 파라미터는 6,500,352개였으며 층 번호 32~39의 여덟 층이 포함됐습니다. 검증 NLL은 기반 모델 1.8312, 선택한 가중치 1.4304였습니다. 선택 파일은 `0000300_adapters.safetensors`이며 가중치 SHA-256은 `5afb412982b4b861f85a9227aa83eef8f844645a8c28e3392914962c7e377152`입니다. NLL 감소만으로 동화의 재미나 사실성이 향상됐다고 판정하지는 않았습니다.

## 5. 기존 평가앱의 계산을 그대로 사용했습니다

새 문제 24개를 먼저 고정하고 Astra, Fable, 학습 전 Qwen, 기존 302편 SFT를 실행했습니다. 새 학습이 끝난 뒤 같은 문제에 새 Qwen을 추가했습니다. 기존 모델의 출력과 심판 결과를 유리하게 다시 생성하지 않았습니다.

새 비교 문제 24개도 후보 출력 전에 고정했습니다. 기존 24개와 추가 12개 문제는 이번부터 원인 분석과 수정에 사용하는 개발 자료입니다. 새 문제의 결과를 보고 같은 문제에 맞춰 수정한 뒤 독립 평가라고 부르지 않겠습니다. 이 단계까지는 로컬 실행으로 API 비용이 없었습니다. 이후 추가 심판 비용은 최대 1.50달러로 승인받았으며, 실제 사용액은 11절에 기록했습니다.


### 9-1. 같은 오류를 먼저 재현했습니다

기존 실패 문제에서 학습 전과 학습 후 출력을 각각 6편씩 다시 만들었습니다. 같은 모델 파일, 어댑터, 프롬프트, 난수 시드와 생성 설정에서 이전 원문 12편이 모두 글자 단위로 같았습니다. 이번 반복 오류를 평가 기록이 섞여 생긴 현상으로 설명할 근거는 없었습니다.

학습 후 모델이 잘못 생성한 원고에는 `Uncle Leo`가 뒤에서 `Aunt Leo`로 바뀌거나, 박수 소리만 이어지다가 2,968토큰 상한에 닿는 사례가 있었습니다. 이름을 유지하라는 지시만 추가한 조건에서도 다른 반복이 발생했습니다. 공통 지시를 학습 때의 짧은 문장으로 바꾼 조건도 반복을 완전히 없애지 못했습니다.

어댑터의 일반 attention 부분과 linear attention 부분을 따로 적용하고, 75단계 저장본도 비교했습니다. 어느 한 종류의 층만 원인이라고 결론 내릴 결과는 아니었습니다. 전체 학습분을 적용하는 강도와 출력 선택 방식이 함께 영향을 주는지 후속 비교 대상으로 남겼습니다.

### 9-2. 반복이 줄어도 사건 오류는 남았습니다

기존 실패 6문제와 정상 대조 6문제에서 수정 후보를 골랐습니다. 후보는 이미 학습한 어댑터의 기여를 절반으로 낮추고, 공식 권장 생성 설정과 이름·관계·장면 진행을 유지하라는 지시를 함께 적용한 조건입니다. 새 경사하강 학습을 한 것이 아니라 같은 학습본의 추론 경로를 바꾼 실험입니다.

이 12문제에서 기존 학습본은 상한 도달 2편, 반복 경고 4편, 동일 이름의 호칭 충돌 1편이었습니다. 수정 후보는 세 항목 모두 0편이었습니다. 다만 분량 조건을 지킨 원고는 기존 3편, 후보 2편으로 줄었습니다. 이 수치는 후보를 선택할 때 본 개발 결과이므로 독립적인 개선 증거가 아닙니다.

실제 문장도 대조했습니다. 수정 후보에는 눈을 감고 물결을 센다는 문장, 꽃봉오리를 흰 물감으로 칠하는 결말이 남았습니다. 다른 후보에서는 두 아이의 대화가 아이와 이모의 대화로 바뀌었습니다. 반복 지표와 이름 정규식으로는 이러한 인과·역할 오류를 잡을 수 없었습니다. 이 검토는 제가 사용하는 에이전트의 원문 대조이며, 사람 평가나 전문가 검수가 아닙니다.

후보 설정은 새 문제를 생성하기 전에 고정했습니다. 학습 전·후의 기존 조건과 학습 전·후의 수정 조건, 총 네 조건으로 24개 문제를 생성했습니다. 이전 문제를 잘 풀게 된 것과 새로운 문제에서도 나아진 것을 구분하려는 비교입니다.

## 10. 평가앱이 실패 결과를 숨기는 경로를 고쳤습니다

앱도 별도로 확인했습니다. 실측 결과가 빈 상태에서 평가·결과 탭을 열면 데모 대결이 채워지는 경로가 있었습니다. 또 정상 완료나 부분 완료 뒤 <span class="term" data-tip="진행 상태를 통째로 저장해둔 지점. 중단되거나 크레딧이 떨어져도 완료분을 다시 호출하지 않고 그 지점부터 이어서 실행할 수 있다.">체크포인트</span>를 지울 때, 실패한 생성의 개수만 남고 원고와 실패 사유가 사라졌습니다.

실측이 비어 있으면 결과 없음으로 표시하도록 바꿨습니다. 실패 원고·실패 사유·응답 메타데이터는 완료 후에도 저장하며, 모델별 유효·실패 생성 수를 함께 보여줍니다. 유효한 심판 판정이 전혀 없는 모델에는 초기값 1,000점을 순위처럼 표시하지 않습니다. 오래된 저장본에 생성 내역이 없으면 실패 0건 대신 내역 미기록으로 표시합니다.

기존 Python 테스트 46개와 새 브라우저 함수 회귀 테스트를 통과했습니다. Chrome에서도 빈 실측에 데모가 들어가지 않고 실패 사유가 표시되는 것을 확인했습니다. 수정은 `little-bard`의 `dab8412` 커밋으로 반영했습니다. 기존 실측 아카이브는 수정하지 않았으며, 이번 모델 비교도 이전 앱에서 고정한 심판 프롬프트와 집계 함수를 사용합니다. 앱 오류를 고친 일을 모델 성능 향상으로 계산하지 않기 위해서입니다.

## 11. 새 24문제에서 반복 감소와 선호 변화를 확인했습니다

후보를 고른 뒤 새 문제에서 총 96편을 생성했습니다. 이름·관계 유지, 유한한 반복과 장면 진행, 수량·위치·상태 보존을 각각 8문제로 구성한 회귀 평가입니다. 7세 보호자 동반 읽기와 180~230단어라는 조건을 사용했습니다. 일반적인 동화 전체를 대표하는 무작위 시험은 아닙니다. 원고는 조건별 한 시드로 만들었고, 이번 문제를 학습 데이터에 넣지 않았습니다.

| 조건 | 상한 종료 | 반복 경고 | 분량 준수 | 상대 점수 |
|---|---:|---:|---:|---:|
| 학습 전 · 기존 생성 | 0/24 | 0/24 | 1/24 | 993.2 |
| 300편 학습 · 기존 생성 | 1/24 | 4/24 | 11/24 | 913.0 |
| 학습 전 · 수정 생성 | 0/24 | 0/24 | 2/24 | 938.6 |
| 어댑터 기여 50% · 수정 생성 | 0/24 | 0/24 | 6/24 | 1155.1 |

수정 생성은 공식 권장 출력 설정과 이름·관계·장면 진행 지시를 함께 넣은 조건입니다. 수정 후보는 이 설정에 어댑터 기여 50%를 적용했습니다. 앞선 절의 교사 모델을 포함한 점수와는 문제·경쟁 모델이 달라 절댓값을 비교할 수 없습니다. 기존 학습본에서 상한에 닿은 1편은 선호 비교에서 제외하고 실패율에 남겼습니다. 따라서 선호 점수는 형식상 유효한 원고에 조건부입니다.

GLM 5.1과 Kimi K2.6이 141개 원고 쌍을 순서를 바꿔 평가해 564회 호출했습니다. 두 심판을 합산했을 때뿐 아니라 각 심판의 순위에서도 수정 후보가 1위였습니다. 기존 학습 전 모델과 수정 후보의 직접 비교는 후보 우세 24건, 학습 전 우세 5건, 순서 평균 동률 19건이었습니다. 같은 수정 생성 조건에서 학습 전과 후보를 비교하면 후보 우세 30건, 학습 전 우세 1건, 평균 동률 17건입니다. 각각 24문제에 두 심판이 판정한 결과로, 48명의 독립 평가가 아닙니다.

### 11-1. 심판의 이름만으로 신뢰도를 정하지 않았습니다

먼저 인물 호칭 오류와 끝나지 않는 반복을 일부러 넣은 두 원고 쌍을 검사했습니다. 두 순서를 합친 4회에서 GLM·Astra·Fable은 모두 기대한 원고를 골랐고, Kimi는 3회였습니다. 나머지 1회에서 Kimi는 Uncle이 Aunt로 바뀐 오류를 언급하고도 전체 품질 차이가 작다며 동점으로 처리했습니다. 오류를 보지 못한 것과 판정에서 가볍게 취급한 것을 구분했습니다. 두 종류의 오류만 검사했으므로 일반적인 심판 정확도로 환산하지 않았습니다.

전체 비교에서도 순서에 민감한 결과가 있었습니다. 순서를 원래대로 환산했을 때 판정이 정확히 같지 않은 쌍은 GLM 83/141, Kimi 25/141이었습니다. 여기에는 승패가 뒤집힌 경우뿐 아니라 승패와 동점 사이가 바뀐 경우도 포함됩니다. 순서 교환 평균만으로 문제가 모두 사라졌다고 볼 수 없습니다.

전체 결과를 보기 전에 범주별 2개씩 고른 6문제에는 Astra와 Fable을 추가 심판으로 사용했습니다. 같은 수정 생성 조건의 학습 전과 후보를 비교했고, 전체 순위에 합산하지 않았습니다. 예산 안에서 두 심판이 모두 완료한 5문제는 다음과 같습니다.

| 심판 | 학습 전 우세 | 수정 후보 우세 | 순서 평균 동률 |
|---|---:|---:|---:|
| GLM 5.1 | 0 | 2 | 3 |
| Kimi K2.6 | 0 | 4 | 1 |
| Astra | 1 | 3 | 1 |
| Fable 5.1 | 1 | 3 | 1 |

이 표는 모두 같은 5문제입니다. 마지막 22번은 다음 요청의 최대 예상 비용까지 예약하면 1.50달러를 넘어서 호출 전에 중단했습니다. 결과가 나쁜 문제를 제외한 것이 아닙니다. 교사 원고를 만든 모델 계열의 문체 선호 가능성과 작은 표본도 남아 있어, 이 표를 사람 평가의 대체 근거로 삼지 않았습니다.

이번 추가 비용은 600회 호출에 **1.3361123달러**입니다. 전체 누적은 확인된 청구액 34.2885338달러, 과거 실패 호출의 미확정 예약액을 포함하면 39.2030259달러입니다. 확인된 금액과 비용 상한 관리용 예약액을 구분했으며, 추가 1.50달러와 누적 40달러 한도를 모두 지켰습니다.

### 11-2. 점수가 올라도 이름 오류는 해결되지 않았습니다

수정 후보 24편을 원문 대조하자 정규식이 놓친 오류가 남아 있었습니다. `Grandmother Ada`와 함께 있던 아이가 끝에서 갑자기 grandfather의 손을 잡았습니다. `Amara`를 `A-N-A-M-A-R-A`라고 철자화하면서 맞다고 서술한 경우도 있었습니다. `FIRST STOP`을 세 단어라고 하거나 주황색 마커로 노란 별을 그리는 사건 오류도 있었습니다. 이 확인은 에이전트의 원문 대조이며 사람 검수가 아닙니다.

학습 전 모델에 수정 생성 설정만 적용한 조건에서도 `Benji`를 `G-E-N-J-I`로 쓰는 오류가 나왔습니다. 따라서 이름 오류 전부를 학습 데이터나 어댑터 하나의 탓으로 돌릴 수 없습니다. 이름 세 개와 시드 두 개로 짧은 후속 철자 검사를 했을 때 presence penalty 유무에 따른 정답 수 차이는 없었습니다. 이 검사는 목표 철자를 입력에 명시한 복사에 가까운 과제여서, 장문 동화의 이름 유지 문제까지 해결했다고 볼 수 없습니다.

08번의 torch 뜻과 17번의 종이 접힘 지시에는 문항 자체의 모호성도 있었습니다. 원래 결과를 유지하고 두 문제를 뺀 사후 민감도 분석을 별도로 남겼습니다. 제외 후에도 후보가 1위였지만, 이를 원래부터 정한 주 평가처럼 제시하지 않았습니다.

이번 결과는 기존 학습본의 반복 문제를 줄이고 자동 선호 평가에서 개선 신호를 얻은 데까지입니다. 새 경사하강 학습이나 DPO는 하지 않았습니다. 분량과 인물·사건 보존이 아직 부족해 운영 모델은 유지합니다. 이 문제들을 다음 수정에 활용한다면 이후 확인에는 다시 새로운 줄거리와 이름, 여러 시드와 사람의 블라인드 검토가 필요합니다.

## 12. NDL로 어휘 조건을 명시하는 방법을 검토했습니다

수준에 맞는 원고를 만들 때 사용할 자료로 New Dolch List(NDL) 1.1도 확인했습니다. 어린이 영어를 위한 874개 headword 목록이며, NGSL 전체와는 별개입니다. 공식 사이트에서 교육용 활용형, 연구용 활용형, 빈도 통계 파일을 내려받고 원본 해시를 보존했습니다. 빈도 파일의 순위는 1~874가 각각 한 번씩 있었습니다. 파일 행은 알파벳순이므로 첫 N행을 초급 어휘로 가져오면 안 됩니다.[^ndl]

교수님이 전달한 Profiler 화면은 7개 구간이지만 NDL Kids Story Creator 공식 설명은 5개의 누적 단계입니다. 둘의 단계 번호를 같은 것으로 처리하지 않았습니다. NDL 소개의 약 90%는 어린이 자료에서 목록이 차지하는 비율이고, Story Creator의 약 98%는 생성 목표입니다. 특정 아이의 이해율이 아닙니다. 실제로 98% 임계치를 다른 성인 학습자 집단에서 재현한 연구도 원래 결과를 완전히 재현하지 못했습니다. 어린이용 합격선으로 그대로 적용하지 않겠습니다.[^ndl-tools][^coverage]

활용 방향은 단어 목록을 그대로 정답 데이터로 학습하는 것이 아닙니다. 목록 버전·어휘 조건·읽기 방식과 유지해야 할 인물·사건을 입력에 명시하고, 그 조건을 지키는 완성 원고를 선별하는 방식입니다. 같은 줄거리의 수준별 원고를 만들 경우 모두 같은 데이터 분할에 넣어, 쉬운 판본을 학습하고 어려운 판본을 시험하는 누수를 피해야 합니다.

단어 포함률만 보상으로 주는 방식도 피합니다. 쉬운 한 문장을 계속 반복하면 수치는 높아질 수 있습니다. 고유명사·축약형·소유격·의성어를 어떻게 계산했는지 남기고, 페이지별 새 단어의 밀도와 이야기의 사건 보존을 함께 확인해야 합니다. 특히 이름을 목록 밖 단어라고 바꾸는 규칙은 이번 이름 변경 오류를 악화시킬 수 있습니다.

다음 비교는 학습 전 모델에 어휘 조건만 명시한 기준선부터 시작하는 설계입니다. 그 뒤 별도의 학습 소재로 SFT와 검증된 <span class="term" data-tip="같은 입력에 대한 두 응답 중 어느 쪽을 더 선호하는지 표시한 데이터 한 쌍. DPO에 쓰려면 승자·패자뿐 아니라 생성 정책·판정 유효성·중복·누수를 함께 관리해야 한다.">선호쌍</span>을 비교하려 합니다. 이번 단계에서는 자료 확인과 설계만 했으며 NDL 조건 학습, 유료 원고 추가 생성, 아동 대상 검증은 수행하지 않았습니다. NDL 포함률을 <span class="term" data-tip="영어 독자의 읽기 능력과 텍스트 난이도를 같은 척도에 표시하는 상용 지표. 텍스트 측정은 어휘의 빈도와 문장 길이 같은 특성을 사용하며, 이 프로젝트의 가독성 공식 합성값은 공인 Lexile이 아니다.">Lexile</span>·AR·CEFR 점수로 변환하지도 않았습니다.
