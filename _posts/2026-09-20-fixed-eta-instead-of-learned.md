생성이 도는 동안 화면에 "약 19분 남았어요"가 떴다. 같은 날 같은 크기의 책을 실측하니 9분 32초였다. 두 배 차이다.

## 실측

인터뷰(사람이 답하는 시간)를 빼고 단계별로 쟀다. 값은 워커 로그의 단계 시작·종료 타임스탬프와 관측 트레이스에서 가져왔다.

| 단계 | 소요 |
|---|---|
| 원고 생성(본문 24쪽 + 심사 3회 + 배역 점검 + 어휘 재작성) | 3분 57초 |
| 그림 단계 전체 | 5분 35초 |
| 표지·뒤표지 | 1분 48초 |
| 입력 심사 7건 병렬 | 9.4초 |
| 초판 <span class="term" data-tip="한 장의 이미지를 2×2로 나눠 네 쪽을 동시에 그리고, 받은 뒤 네 칸으로 잘라 각각의 쪽으로 쓰는 방식. 호출 한 번에 네 쪽을 처리해 쪽당 비용이 내려가지만, 칸 하나에 배정되는 출력 토큰은 단일 이미지보다 적다.">4칸 이미지</span> 7장 | 64.5초 |
| <span class="term" data-tip="생성된 결과물을 별도의 모델 호출로 검사해 통과 여부와 지적 사항을 돌려받는 단계. 안전, 글자 일치, 만듦새, 참조 일치처럼 항목을 나눠 둔다.">출력 심사</span> 7건 | 71.6초 |
| <span class="term" data-tip="심사가 지적한 자산만 골라 다시 생성하는 단계. 한 번만 수행하고 그 결과를 다시 심사하지 않으면, 교정이 빗나가도 그대로 출고된다.">재작화</span> 8장 | 59.7초 |
| 합계 | 9분 32초 |

## 왜 두 배가 나왔나

추정기는 최근 완료한 책의 소요를 표본으로 모아 평균과 <span class="term" data-tip="정렬한 값에서 위에서 25% 지점에 있는 값. 평균보다 느린 쪽을 더 반영해 보수적인 추정을 만들지만, 그만큼 과거의 느린 실행에 끌려간다.">75분위</span>로 기대 소요를 잡고 있었다. 이미지 수가 비슷한 책끼리 비교하는 장치도 있었다.

문제는 표본이 과거라는 점이다. 그 표본에는 표지 재시도가 잦던 시기와 그림을 순차로 그리던 시기의 실행이 섞여 있었다. 75분위는 그중 느린 쪽을 따라간다. 그래서 최근에 바꾼 것들(병렬 생성, 이미지 품질 고정, 심사 입력 축소)이 안내에 반영되려면 그만큼 새 표본이 쌓여야 했다.

스스로 배우는 추정은 환경이 안정적일 때 유리하다. 파이프라인을 일주일에 몇 번씩 바꾸는 동안에는 과거가 현재를 대표하지 않는다.

## 바꾼 것

학습을 버리고 설정값을 그대로 쓰게 했다.

- 원고 240초 + 그림 300초 = 540초(9분)
- 이미지 수와 무관하게 같은 값. 표지를 먼저 그리고 나머지를 병렬로 그리므로 소요가 장수에 거의 비례하지 않는다. 실측에서 24쪽 그림 단계가 5분 35초였다.
- 환경변수로 조정 가능. 실제 소요가 달라지면 값 하나를 고친다.

같이 지운 것이 있다. 학습에만 쓰이던 조회 포트, 저장소 <span class="term" data-tip="동결한 베이스 모델 옆에 붙여 학습하는 작은 추가 가중치 묶음. 파일이 작아도 층 이름과 배열 모양이 실행 프레임워크의 형식과 맞지 않으면 그대로 옮겨 쓸 수 없다.">어댑터</span> 구현, 리포지토리 질의, 그리고 학습을 검증하던 테스트다. 남겨 두면 "이 값이 어디서 오는가"를 읽는 사람이 두 경로를 다 따라가야 한다.

진행률 퍼센트 계산, 워커가 보고하는 완료 개수 반영, 완료 전 99% 상한은 건드리지 않았다.

## 대가

추정이 더 이상 스스로 따라가지 않는다. 파이프라인이 느려지거나 빨라지면 안내가 틀린 채로 남는다. 그래서 "생성 구조를 크게 바꾸면 이 값도 함께 고친다"를 계약으로 적어 두고, 코드 주석과 이슈 양쪽에 남겼다.

이 교환을 받아들인 이유는 두 가지다. 첫째, 사용자가 보는 것은 예측의 정교함이 아니라 예측이 맞는지다. 19분이라고 하고 9분 만에 끝나는 것은 정확한 모델의 결과가 아니라 그냥 틀린 안내다. 둘째, 지금은 파이프라인을 자주 고치는 구간이라 학습이 따라올 시간 자체가 없다.

안정기에 들어가면 다시 학습형으로 돌릴 수 있다. 그때는 표본에 기간 상한을 두거나, 코드 릴리스 이후의 실행만 쓰는 식으로 과거를 끊어야 한다.
