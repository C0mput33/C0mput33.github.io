책을 만드는 동안 화면에 "약 19분 남았어요"가 떴다. 같은 날 같은 크기의 책을 직접 재 보니 9분 32초에 끝났다. 안내가 실제의 두 배였다.

## 실제로 걸린 시간

사람이 답하는 인터뷰 시간은 뺐다. 워커 로그에 찍힌 단계별 시작·종료 타임스탬프와 관측 트레이스에서 값을 뽑으니 이렇게 나왔다.

| 단계 | 소요 |
|---|---|
| 원고 생성(본문 24쪽 + 심사 3회 + 배역 점검 + 어휘 재작성) | 3분 57초 |
| 그림 단계 전체 | 5분 35초 |
| 표지·뒤표지 | 1분 48초 |
| 입력 심사 7건 병렬 | 9.4초 |
| 초판 <span class="term" data-tip="한 장의 이미지를 2×2로 나눠 네 쪽을 동시에 그리고, 받은 뒤 네 칸으로 잘라 각각의 쪽으로 쓰는 방식. 호출 한 번에 네 쪽을 처리해 쪽당 비용이 내려가지만, 칸 하나에 배정되는 출력 토큰은 단일 이미지보다 적다.">4칸 이미지</span> 7장 | 64.5초 |
| <span class="term" data-tip="생성된 결과물을 별도의 모델 호출로 검사해 통과 여부와 지적 사항을 돌려받는 단계. 안전, 글자 일치, 만듦새, 참조 일치처럼 항목을 나눠 둔다.">출력 심사</span> 7건 | 71.6초 |
| <span class="term" data-tip="심사가 지적한 자산만 골라 다시 생성하는 단계. 한 번만 수행하고 그 결과를 다시 심사하지 않으면, 교정이 빗나가도 그대로 출고된다.">재작화</span> 8장 | 59.7초 |
| 합계 | 9분 32초 |

## 두 배가 나온 이유

추정기는 최근에 끝난 책들의 소요 시간을 모아 평균과 <span class="term" data-tip="정렬한 값에서 위에서 25% 지점에 있는 값. 평균보다 느린 쪽을 더 반영해 보수적인 추정을 만들지만, 그만큼 과거의 느린 실행에 끌려간다.">75분위</span>로 기대 소요를 잡았다. 이미지 수가 비슷한 책끼리 묶어 비교하는 장치까지 붙여 뒀다.

표본을 열어 보니 전부 옛날 실행이었다. 표지 재시도가 잦던 시기 것도 있었고, 그림을 한 장씩 순서대로 그리던 시기 것도 남아 있었다. 75분위는 그런 느린 기록 쪽으로 끌려간다. 나는 그사이 병렬 생성을 넣었고, 이미지 품질을 고정했고, 심사 입력도 줄였다. 안내가 이걸 따라잡으려면 새 표본이 쌓일 때까지 기다리는 수밖에 없었다.

그 무렵 나는 파이프라인을 일주일에 몇 번씩 고치고 있었다. 지난주 실행으로 오늘을 짐작하는 게 애초에 무리였다.

## 고정값으로 바꿨다

학습을 걷어내고 설정값을 그대로 쓰게 했다.

- 원고 240초 + 그림 300초 = 540초(9분)
- 이미지 수가 달라도 같은 값을 쓴다. 표지를 먼저 그리고 나머지는 병렬로 그려서, 소요가 장수에 거의 비례하지 않는다. 실측에서도 24쪽 그림 단계가 5분 35초였다.
- 환경변수로 바꿀 수 있다. 실제 소요가 달라지면 값 하나만 고치면 된다.

학습에만 쓰던 코드는 지웠다. 조회 포트, 저장소 <span class="term" data-tip="동결한 베이스 모델 옆에 붙여 학습하는 작은 추가 가중치 묶음. 파일이 작아도 층 이름과 배열 모양이 실행 프레임워크의 형식과 맞지 않으면 그대로 옮겨 쓸 수 없다.">어댑터</span> 구현, 리포지토리 질의, 학습을 검증하던 테스트까지 다. 남겨 두면 나중에 코드를 읽는 사람이 "이 값이 어디서 오지?" 하면서 두 경로를 다 따라가게 된다.

진행률 퍼센트 계산, 워커가 보고하는 완료 개수 반영, 완료 전 99% 상한은 손대지 않았다.

## 감수한 것

대신 추정은 더 이상 알아서 따라오지 않는다. 파이프라인이 느려지든 빨라지든 안내는 틀린 채로 남는다. 그래서 "생성 구조를 크게 바꾸면 이 값도 같이 고친다"를 규칙으로 정해 코드 주석과 이슈에 둘 다 적어 뒀다.

그래도 이쪽을 골랐다. 19분이라고 해 놓고 9분 만에 끝나면, 추정 방식이 아무리 정교해도 사용자한테는 그냥 틀린 안내다. 일주일에 몇 번씩 고치는 동안엔 학습이 따라올 틈도 없었다.

파이프라인이 안정되면 학습형으로 돌아갈 생각은 있다. 그때는 표본에 기간 상한을 두거나 코드 릴리스 이후 실행만 쓰게 해서, 오래된 기록부터 끊어 낼 것이다.
